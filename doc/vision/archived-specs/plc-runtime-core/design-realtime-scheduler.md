## 概述

本文档描述了Uranus PLC系统中1ms高精度实时调度器的设计理念和架构方案。该调度器是整个PLC系统的核心，负责确保各种任务能够在严格的时间约束下可靠执行。

## 设计目标

### 性能指标
- **调度精度**: ±10μs (在RT-PREEMPT Linux下)
- **最大抖动**: <50μs (99%的情况下)
- **任务切换开销**: <5μs
- **支持任务数**: 最多64个并发任务
- **优先级级别**: 32个优先级级别 (0最高，31最低)

### 功能要求
- 支持循环任务、中断任务、自由运行任务
- 基于优先级的抢占式调度
- 任务间通信和同步
- 实时性能监控和统计
- 跨平台支持 (Windows/Linux/RTOS)

## 设计理念

### 确定性调度
实时调度器的核心是提供确定性的任务执行时间。通过以下设计原则实现：

1. **固定优先级调度**: 采用静态优先级分配，高优先级任务总是优先执行
2. **抢占式调度**: 高优先级任务可以立即抢占低优先级任务
3. **时间轮算法**: 使用O(1)复杂度的时间轮管理周期性任务
4. **无锁编程**: 关键路径避免使用互斥锁，减少不确定性延迟

### 高精度时间管理
为实现1ms精度调度，采用多层次时间管理策略：

1. **硬件时钟源选择**: 优先使用RDTSC、硬件定时器等高精度时钟
2. **时钟校准机制**: 定期校准系统时钟，补偿时钟漂移
3. **忙等待策略**: 最后阶段使用忙等待确保精确时间对齐
4. **时间预算管理**: 为每个任务分配时间预算，防止任务超时

## 核心架构

### 分层架构设计

调度器采用清晰的分层架构，确保各层职责明确：

1. **调度器接口层**: 提供统一的任务管理API，屏蔽内部复杂性
2. **任务管理层**: 负责任务生命周期管理和状态维护
3. **调度算法层**: 实现多种调度策略，支持算法切换
4. **时间管理层**: 提供高精度时间服务和时钟同步
5. **平台抽象层**: 封装操作系统差异，支持跨平台部署

### 任务模型架构

#### 任务分类体系
- **循环任务**: 周期性执行，适用于控制逻辑和数据采集
- **中断任务**: 事件驱动执行，适用于紧急响应和异常处理
- **自由运行任务**: 连续执行，适用于后台服务和通信处理

#### 任务状态管理
任务状态机设计确保状态转换的确定性：
- **就绪态**: 等待CPU资源分配
- **运行态**: 占用CPU执行代码
- **等待态**: 阻塞等待外部条件
- **挂起态**: 暂停执行但保持上下文
- **终止态**: 完成执行或异常退出

#### 优先级分级策略
32级静态优先级系统，确保关键任务优先执行：
- **系统级 (0-7)**: 安全监控、中断处理等关键任务
- **控制级 (8-15)**: PLC逻辑、运动控制等实时任务
- **通信级 (16-23)**: 网络通信、I/O处理等准实时任务
- **服务级 (24-31)**: 日志记录、诊断等后台任务

## 高精度时间管理

### 时钟源架构设计

#### 多层次时钟源策略
调度器支持多种时钟源，根据平台和精度要求自动选择：

- **系统时钟**: 标准系统时钟，精度约1ms，兼容性最好
- **高分辨率时钟**: 操作系统提供的高精度时钟，精度约1μs
- **硬件时间戳计数器**: CPU内置计数器，纳秒级精度，性能最优
- **硬件定时器**: 专用硬件定时器，最高精度和稳定性
- **网络同步时钟**: PTP等网络时间协议，支持分布式同步

#### 时钟校准机制
为确保长期运行的时间精度，实现多级校准策略：

1. **启动校准**: 系统启动时进行基准校准
2. **周期校准**: 定期校准时钟频率和偏移
3. **动态校准**: 根据温度等环境因素动态调整
4. **漂移补偿**: 检测和补偿时钟长期漂移

### 精确等待策略

#### 混合等待算法
结合多种等待机制，实现最优的时间精度：

1. **粗粒度等待**: 使用系统调用进行毫秒级等待
2. **细粒度等待**: 使用高精度定时器进行微秒级等待
3. **忙等待**: 最后阶段使用CPU忙等待确保纳秒级精度
4. **自适应调整**: 根据系统负载动态调整等待策略

## 调度算法架构

### 多算法支持策略

#### 核心调度算法
调度器支持多种调度算法，可根据应用场景选择：

1. **固定优先级调度**: 经典的抢占式优先级调度，适用于大多数实时应用
2. **时间轮调度**: 高效的周期任务调度，O(1)复杂度，适用于大量周期任务
3. **截止时间调度**: 基于任务截止时间的调度，适用于硬实时系统
4. **混合调度**: 结合多种算法的优势，动态选择最优策略

#### 优先级队列管理
- **多级队列**: 32个优先级队列，支持快速任务查找
- **位图索引**: 使用位图快速定位非空队列
- **时间片管理**: 支持时间片轮转和预算控制
- **负载均衡**: 动态调整队列负载，避免饥饿现象

### 时间轮调度机制

#### 设计理念
时间轮算法专门优化周期性任务的调度效率：

- **O(1)复杂度**: 插入、删除、查找操作都是常数时间
- **内存友好**: 紧凑的数据结构，缓存友好
- **扩展性好**: 支持大量并发周期任务
- **精度可调**: 支持不同时间精度的配置

## 跨平台实时优化

### 平台适配策略

#### Windows平台优化
针对Windows系统的实时性能优化：

1. **多媒体定时器**: 设置系统定时器分辨率到最高精度
2. **进程优先级**: 设置实时优先级类和时间关键线程优先级
3. **高精度定时器**: 使用可等待定时器实现精确等待
4. **性能计数器**: 利用QueryPerformanceCounter获取高精度时间
5. **CPU亲和性**: 绑定调度器到专用CPU核心

#### Linux平台优化
针对Linux系统的实时性能优化：

1. **实时调度策略**: 使用SCHED_FIFO实时调度策略
2. **内存锁定**: 锁定进程内存页，避免页面交换
3. **CPU亲和性**: 绑定到专用CPU核心，减少上下文切换
4. **高精度定时器**: 使用timerfd和clock_nanosleep
5. **内核参数**: 优化内核实时性能参数

### 实时性能调优

#### 系统级优化
- **中断隔离**: 将硬件中断路由到非实时CPU核心
- **CPU频率锁定**: 禁用动态频率调整，保持最高性能
- **内存预分配**: 预分配所需内存，避免运行时分配
- **缓存优化**: 优化数据结构布局，提高缓存命中率

## 调度器核心流程

### 主调度循环设计

#### 循环架构
调度器主循环采用固定周期的设计模式：

1. **时间同步**: 与高精度时钟同步，确保精确的调度周期
2. **任务发现**: 扫描时间轮和中断队列，发现就绪任务
3. **调度决策**: 根据调度算法选择下一个执行任务
4. **抢占检查**: 判断是否需要抢占当前运行任务
5. **任务执行**: 执行选定任务并监控其性能
6. **统计更新**: 更新性能统计和监控数据
7. **周期等待**: 精确等待到下一个调度周期

#### 调度决策流程
- **优先级比较**: 基于任务优先级进行调度决策
- **时间约束检查**: 验证任务的时间约束和截止时间
- **资源可用性**: 检查所需资源的可用性
- **负载均衡**: 考虑系统负载进行调度优化

### 任务执行管理

#### 执行控制机制
- **上下文切换**: 高效的任务上下文切换管理
- **异常处理**: 任务执行异常的捕获和处理
- **超时保护**: 防止任务执行时间超限
- **性能监控**: 实时监控任务执行性能

## 错误处理与故障恢复

### 错误处理架构

#### 错误分类体系
调度器识别和处理多种类型的错误：

1. **任务级错误**: 任务执行超时、栈溢出、异常退出等
2. **系统级错误**: 内存耗尽、系统过载、硬件故障等
3. **时间相关错误**: 错过截止时间、时钟漂移、调度延迟等
4. **资源相关错误**: 资源竞争、死锁、资源泄漏等

#### 处理策略框架
针对不同错误类型采用相应的处理策略：

- **忽略策略**: 对于轻微的非关键错误
- **日志记录**: 记录错误信息用于后续分析
- **任务重启**: 重启出错的任务，恢复正常执行
- **性能降级**: 降低系统性能要求，确保稳定运行
- **紧急停止**: 对于严重错误，触发安全停机

### 故障恢复机制

#### 自动恢复策略
- **错误检测**: 实时监控系统状态，及时发现异常
- **影响评估**: 评估错误对系统整体的影响程度
- **恢复决策**: 根据错误类型和影响选择恢复策略
- **状态恢复**: 恢复系统到稳定的运行状态

#### 渐进式降级
当系统出现问题时，采用渐进式降级策略：
1. **警告阶段**: 记录警告信息，继续正常运行
2. **性能降级**: 降低非关键任务优先级
3. **功能限制**: 暂停部分非核心功能
4. **安全模式**: 只保留最关键的安全功能

### 性能指标定义与测量

#### 核心指标规范
- **调度周期 (Cycle Time)**: 目标1ms ±10μs
- **调度抖动 (Jitter)**: <50μs (99%情况下)
- **任务切换延迟**: <5μs (上下文切换开销)
- **中断响应时间**: <20μs (硬件中断到任务执行)
- **系统开销**: <5% CPU占用率 (空闲时)

#### 测量方法与工具
- **采样窗口**: 连续10000个周期的统计样本
- **统计指标**: 
  - 最小/平均/最大周期时间
  - 绝对抖动 (|实际周期 - 目标周期|)
  - 相对抖动 (连续周期间的差值)
  - 超时次数 (overrun count)
- **测量工具**: 
  - 内置性能计数器
  - 外部逻辑分析仪验证
  - 专用实时测试套件

#### 测试用例与判定标准
```
测试场景1: 空载基线测试
- 条件: 单一1ms周期任务，无其他负载
- 判定: 99%周期在990-1010μs范围内
- 抖动: <10μs (标准差)

测试场景2: 多任务负载测试  
- 条件: 8个不同优先级任务并发
- 判定: 高优先级任务抖动<50μs
- 抢占: 高优先级任务100%及时执行

测试场景3: 系统干扰测试
- 条件: 网络I/O + 磁盘I/O + 内存分配
- 判定: 实时任务性能退化<20%
- 恢复: 干扰消除后1秒内恢复正常
```

### 运行时可观测性要求

#### 统计数据接口
调度器必须提供以下实时统计数据：

```cpp
struct SchedulerMetrics {
    // 周期统计
    uint64_t totalCycles;           // 总调度周期数
    uint64_t missedDeadlines;       // 错过截止时间次数
    double avgCycleTime;            // 平均周期时间 (μs)
    double maxCycleTime;            // 最大周期时间 (μs)
    double minCycleTime;            // 最小周期时间 (μs)
    
    // 抖动统计
    double avgJitter;               // 平均抖动 (μs)
    double maxJitter;               // 最大抖动 (μs)
    double jitterStdDev;            // 抖动标准差
    
    // 任务统计
    uint64_t contextSwitches;       // 上下文切换次数
    uint64_t preemptions;           // 抢占次数
    double cpuUtilization;          // CPU使用率 (%)
    
    // 错误统计
    uint64_t overruns;              // 任务超时次数
    uint64_t systemErrors;          // 系统错误次数
};
```

#### 数据获取方式
- **拉取接口**: `getSchedulerMetrics()` API调用
- **推送通知**: 异常情况主动通知 (抖动>阈值)
- **历史缓存**: 最近1000个周期的详细数据
- **导出功能**: CSV/JSON格式导出，用于离线分析

#### 监控时序要求
- **统计更新频率**: 每100个周期更新一次
- **实时查询延迟**: <100μs (不影响实时任务)
- **历史数据保留**: 运行期间持续保留
- **内存开销**: <1MB统计数据存储

### 平台策略概述

#### Windows平台实时优化
- **进程优先级**: REALTIME_PRIORITY_CLASS
- **线程优先级**: THREAD_PRIORITY_TIME_CRITICAL  
- **CPU亲和性**: 绑定到专用CPU核心 (Core 1)
- **内存策略**: VirtualLock锁定关键内存页
- **时钟策略**: 1ms多媒体定时器 + QPC精确测量
- **已知限制**: Windows调度器非确定性，抖动较大

#### Linux RT-PREEMPT优化
- **调度策略**: SCHED_FIFO，优先级99
- **CPU隔离**: isolcpus内核参数隔离CPU核心
- **内存锁定**: mlockall(MCL_CURRENT|MCL_FUTURE)
- **中断亲和性**: 将硬件中断路由到非实时核心
- **内核参数**: 
  ```bash
  isolcpus=1 nohz_full=1 rcu_nocbs=1
  intel_idle.max_cstate=0 processor.max_cstate=1
  ```
- **预期性能**: 抖动<10μs，适合硬实时应用

#### 典型干扰源与隔离策略
- **网络中断**: 绑定到非实时CPU核心
- **磁盘I/O**: 使用异步I/O，避免阻塞实时任务  
- **内存分配**: 预分配内存池，避免运行时分配
- **系统调用**: 最小化系统调用，使用用户态同步原语
- **电源管理**: 禁用CPU频率调节和深度睡眠状态
