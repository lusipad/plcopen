# STO / SS1 集成安全边界

> 状态：**集成边界已锁定（2026-07-13）**。本文关闭商用门板 P#8 的
> 文档责任，不实现安全功能，也不形成 IEC 61800-5-2、PLCopen Safety、
> SIL 或 PL 声明。任何安全能力必须由具体机器的风险评估、安全需求规格
> （SRS）、认证安全驱动/安全控制器、独立安全通道及验证证据共同成立。

## 1. 适用范围与依据

本文只回答普通运动库如何与外部 STO/SS1 安全系统共存，避免将功能控制误当
安全功能。规范正文受版权保护；以下只记录 IEC 官方公开条目、预览目录中的
条款定位和项目集成判据，不复制标准正文。

| 来源 | 可核验条目 | 对本文的约束 |
|------|------------|--------------|
| [IEC 61800-5-2:2016 Ed.2.0](https://webstore.iec.ch/en/publication/24556) | 官方摘要：安全相关驱动系统 PDS(SR) 的设计、开发、集成和验证；预览目录 §4.2.3 Stopping functions | STO/SS1 属安全相关驱动子功能，不由普通运动 FB 的命名或轨迹形状自动获得 |
| IEC 61800-5-2:2016 预览目录 | §5.5 SRS、§5.6 安全架构规格、§6 设计开发、§8 验证与确认 | 集成商必须先定义机器风险、目标安全状态、时间与完整性要求，再选驱动和安全架构并验证 |
| [PLCopen Safety](https://www.plcopen.org/standards/safety/) | Safety 与 logic/motion 的集成、认证组织参与；PLCopen Safe Motion 资料入口 | 普通应用可消费安全状态，但不能替代安全请求、确认、超时、诊断和认证执行层 |
| 仓库 [Safety 审计](plcopen-safety-audit.md) | Safe Motion §4.1、§4.2–4.6、§5；缺口 S-01～S-10 | 当前无 SF 生命周期、安全数据类型、safe axis、安全通信或安全认证证据 |

术语边界：

- **STO**：安全系统使驱动不能产生可导致运动的转矩；它不等于普通
  `disable_voltage` 命令、`MC_Power(FALSE)`、软件状态 `Disabled` 或断开
  非安全通信。
- **SS1**：安全系统启动并监控减速过程，满足其 SRS 定义的停止判据后进入
  STO；超时、监控偏差或通信故障必须由安全系统按其安全反应处理。
- 本文不选择 SS1 的具体实现类型、减速斜坡、时间限值或 SIL/PL。这些参数
  必须来自机器风险评估、驱动手册和项目 SRS，库不能提供通用默认值。

## 2. 三域边界

```text
hazard sensors / E-stop / guard
             |
             v
certified safety controller ---- safe fieldbus / hardwired safety ---- PDS(SR)
        |                 safety request + safe confirmation             |
        | non-safety diagnostic mirror                                   | torque
        v                                                                v
application / plcopen executor ---- ordinary setpoint + CiA402 ---- motor/machine
        |
        +---- MC_Stop / MC_Halt / ErrorStop = functional coordination only
```

| 域 | 本项目可做 | 本项目明确不做 |
|----|------------|----------------|
| 普通运动域 | 生成轨迹和普通受控停止；在收到安全需求镜像后停止发新运动、撤销排队命令、冻结重启许可；记录诊断 | 判断安全功能已满足、计算安全完整性、以普通反馈证明安全速度/零速 |
| CiA402 普通驱动域 | 普通状态机、quick stop/disable voltage 请求、普通 fault/状态诊断 | 作为 STO 安全通道、作为 SS1 完成确认、替代 FSoE/PROFIsafe/硬接线安全输入 |
| 独立安全域 | 由集成商选择的安全 PLC/继电器、认证驱动安全功能、安全通信/接线、独立监控 | 不在本仓库实现；不得把 `Servo`、`AxisModel`、普通 ST 或 `FbEmergencyStop` 纳入安全链证明 |

安全域始终具有最高权限：安全请求不得等待普通任务扫描、队列清空、网络恢复
或 `MC_Stop.Done`。普通运动域失败、挂起、复位、掉电或通信丢失，都不得阻止
安全域到达 SRS 指定的安全状态。

## 3. CiA402 与 STO/SS1 交互

### 3.1 允许的普通域配合

| 事件 | 普通运动域动作 | CiA402 普通动作 | 安全域裁决 |
|------|----------------|-----------------|------------|
| SS1 请求出现 | 同拍拒绝新运动，撤销 buffered 命令；可发送普通受控停止作为降低机械冲击的辅助路径 | 可按驱动集成手册请求 quick stop 或保持已使能以执行普通减速 | 独立监控减速；只由安全确认/超时决定何时转 STO |
| STO 请求出现 | 立即停止接受新命令并锁存 restart inhibit；现有轨迹结果不再具有安全意义 | 可请求 disable voltage，但其状态字仅作诊断 | 安全通道直接请求 STO；无需等待普通状态机 |
| STO 已确认 | 保持命令门控；将轴普通状态映射到禁用/错误由宿主策略决定 | 可观察 switch-on-disabled/fault 等普通状态，但不能反推安全确认 | 只有认证安全反馈可确认 STO |
| 安全请求解除 | 仍保持 restart inhibit | 不自动 enable operation | 完成安全复位条件后只发“允许重新武装”，不直接启动运动 |
| 通信/普通任务故障 | 进入普通错误处理并停止发新 setpoint | 普通链路可能不可用 | 安全链必须独立保持有效；按 SRS 执行 SS1/STO 或故障反应 |

### 3.2 禁止的等价替换

- `Cia402Machine::quick_stop` **不是 SS1**：当前类没有独立安全请求/确认、
  安全计时、监控通道或 SIL 证据。
- `Cia402Machine::disable_voltage` **不是 STO**：它只是抽象的普通控制字状态
  转换，不是认证安全输入或安全通信对象。
- `MC_Stop` / `MC_GroupStop` **不是 SS1**：它们是普通规划器的 jerk-limited
  停车命令；任务、反馈、内存或软件故障可能破坏执行，且 Part 1 仍有 D-04
  生命周期偏差。
- `FbEmergencyStop` / `AxisStatus::errorstop` **不是安全急停或 STO**：没有
  双通道、诊断覆盖、复位防重启、独立安全输出或安全完整性证明。
- `communication_ready=false`、软件限位、速度限值和零速阈值都只是普通诊断，
  不得用作 STO/SS1 的唯一安全确认。

## 4. 重启与复位合同

安全需求一旦出现，宿主集成层必须锁存 `restart_inhibit`。解除条件必须全部满足：

1. 安全域报告需求已解除且允许复位；
2. 机器级复位动作符合风险评估（需要手动复位时不得自动完成）；
3. 驱动安全功能已按驱动手册复位，普通通信重新建立；
4. 所有普通运动命令与队列已清空，实际状态重新采集；
5. 重新 enable 与重新开始运动是两个独立动作，复位本身不得产生运动。

`FbReset`、CiA402 `fault_reset` 或通信恢复均不能单独清除该锁存。当前仓库尚无
这一机器级安全集成状态机；实现前必须另立批准矩阵，不能塞入 `AxisModel`。

## 5. 集成商责任矩阵

| 交付物 / 活动 | plcopen 库 | 安全驱动/控制器供应商 | 机器集成商 | 认证/验证方 |
|----------------|-------------|-----------------------|------------|-------------|
| 普通轨迹、普通 Stop/Halt 与命令门控钩子 | 提供并说明非安全边界 | 提供普通驱动接口 | 集成 | 仅作非安全上下文审查 |
| STO/SS1 安全功能、诊断覆盖与安全手册 | 不提供 | 提供认证能力、参数范围、反应时间和限制 | 选型并正确配置 | 核验证书与适用范围 |
| 风险评估、目标安全状态、SIL/PL 与 SRS | 不决定 | 提供产品约束 | **负责** | 审查/确认 |
| 安全 I/O、FSoE/PROFIsafe 或硬接线路径 | 不提供 | 提供兼容接口 | **设计、接线、验证** | 独立验证 |
| SS1 减速时间/斜坡、负载与制动器协调 | 不提供默认值 | 提供驱动限制 | **按机器验证** | 验证最坏工况 |
| STO/SS1 请求与确认的普通诊断镜像 | 可定义非安全只读接口 | 提供状态映射 | 集成且不得用于唯一安全决策 | 检查分域 |
| restart inhibit、手动复位与防意外重启 | 提供普通域钩子时须另批 | 提供驱动复位合同 | **实现机器级互锁** | 验证所有故障/恢复路径 |
| 最终安全声明、验证报告和维护变更控制 | 不声明 | 提供产品证据 | **负责系统声明** | 签字/认证 |

## 6. 集成验收清单

只有下列证据齐备，集成商才能在自己的机器范围内声称 STO/SS1 已集成；本仓
文档本身不满足这些条件：

- [ ] 风险评估和 SRS 指定安全状态、触发源、反应时间、SS1 停止判据、
      STO 转换条件、SIL/PL 与复位策略；
- [ ] 安全驱动/控制器证书、安全手册、适用工作模式和参数范围可追溯；
- [ ] 安全通信或硬接线与普通 EtherCAT/CiA402/串口物理及逻辑分域；
- [ ] 断普通网络、停止 executor、冻结普通任务、破坏反馈时，安全功能仍有效；
- [ ] SS1 正常减速、超时、速度监控偏差、编码器/安全反馈故障均按 SRS 转入
      规定安全反应；
- [ ] STO 请求不等待 `Done`，STO 确认不由普通 statusword、零速或软件状态推断；
- [ ] 最重负载、最高速度、最低/最高电压、制动器与垂直轴下验证停止距离和时间；
- [ ] 安全复位不会自动 enable 或启动，断电重启、通信恢复和普通 fault reset
      不会绕过 `restart_inhibit`；
- [ ] 变更驱动固件、参数、负载、机械传动、安全控制逻辑或通信映射后重新评估
      并执行受影响的验证；
- [ ] 验证记录、测试设备校准、版本与签字可追溯。

## 7. 对外表述

当前允许：

> plcopen 提供普通运动控制与非安全 CiA402 适配原语，可由机器集成商在独立、
> 经验证的安全系统之外进行组合。项目本身不实现或认证 STO/SS1。

当前禁止：

- “内置 STO / SS1 / 安全急停”；
- “SIL-ready / PL-ready / safety-certified”；
- “CiA402 quick stop 等同 SS1”或“disable voltage 等同 STO”；
- 以普通 `ErrorStop`、软件限位、零速或 `MC_Stop.Done` 作为安全完成证据。
