# 分支覆盖基线与门禁口径

> 状态：P#5 已于 2026-07-14 收口；当时固定生产运动栈精确达到 85.006%，
> 85% 分支硬门已启用。H3 于 2026-07-26 新增 `dyn` 支撑库并将其纳入同一
> 固定范围；阈值不放宽，新范围的远端数值待 Coverage Gate 复验。

## 固定统计范围

`long-term-plan.md` 使用了“motion core”一词但没有给出目录集合。为避免按
结果选择有利目录，Linux 覆盖门将操作口径固定为**生产运动栈**：

```text
core/{rt,otg,geom,plan,exec,axis,fb,kin,stream,dyn}/
```

它覆盖 L0-L6 运动实现以及 `kin/stream/dyn` 支撑库。`core/st` 和
`core/adapters` 是架构外圈的纯 sink 消费面，不计入 85% 分支门；但二者
仍计入全 `core/` 90% 行覆盖门和全 `core/` 分支趋势，不能从质量报告中
消失。目录集合一经固定，不得为通过阈值临时增删。

两个口径由 `cmake/coverage_gate.cmake` 使用 gcovr 8.6 独立计算：

- 全 `core/`：行覆盖率必须 `>= 90%`，同时透明报告分支趋势；
- 生产运动栈：固定范围报告并上传 JSON，必须 `>= 85%`。

生产运动栈分支口径固定启用 `--exclude-unreachable-branches` 和
`--exclude-throw-branches`，只消除 GCC 生成的不可达/异常处理噪声。不得
增加逐文件或逐行排除来隐藏正常可达分支。

## 2026-07-13 首测

WSL Ubuntu 24.04、g++、gcovr 8.6 的干净插桩构建首测结果：

| 口径 | 行 | 分支 | 结论 |
|------|----|------|------|
| 全 `core/` | 88.3%（13606/15406） | 74.1%（7388/9968） | 既有 90% 行门因新增代码跌破 |
| 生产运动栈 | 89.4%（9798/10961） | 73.4%（5141/7004） | 距 85% 约 812 条分支 |

将四项 fuzz 从 smoke 提升到 100,000 轮后，全 `core/` 分支仅增约 31 条，
证明继续堆随机次数不是有效补盲方案。

## 已完成补盲批次

首两批只通过公开 API 增加行为断言，未使用私有状态注入或 coverage 排除：

- `exec/sampler`、`plan/path`、`plan/topp_executor` 的空容器、边界采样、
  非法网格与限制校验；
- cam table/spline 的非有限输入、容量、端点和周期回绕；
- Axis 参数写入和 AxisGroup interrupt/continue/override 状态矩阵；
- ST FB 通过 `fb_init/fb_store/fb_cycle/fb_load` 的真实绑定调度。

干净全量复测后：

| 口径 | 行 | 分支 | 相对首测 |
|------|----|------|----------|
| 全 `core/` | 91.0%（14097/15494） | 78.8%（7873/9988） | 行硬门恢复；分支 +485 |
| 生产运动栈 | 91.5%（10108/11049） | 78.4%（5510/7024） | 分支 +369 |

## 2026-07-14 最终补盲与硬门

后续补盲继续只走公开 API 和真实合同测试，覆盖 Axis/Group 生命周期、
Cartesian/窗口、回零、fixed-time OTG、stream、profile、kinematics、cam、
几何原语与 Part 4 回读/路径表。过程中修复了配置 NaN 绕过、飞越式回零
falling/off 判定、窗口 override=0 暂停/恢复及二次曲线 tolerance=NaN 等
真实缺陷；未增加逐文件/逐行排除，也未扩大固定统计目录。

干净插桩构建最终结果：

| 口径 | 行 | 分支 | 结论 |
|------|----|------|------|
| 生产运动栈 | 94.2%（10471/11121） | **85.0%（6004/7062）** | 精确 85.006%，硬门启用 |

`cmake/coverage_gate.cmake` 已在固定生产运动栈 gcovr 命令加入
`--fail-under-branch 85`；阈值以下直接失败，P#5 据此关闭。

`otg/time_optimal.h`、`fb/homing.h` 与 `stream/filter.h`。
