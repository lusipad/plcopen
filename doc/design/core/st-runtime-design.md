## 1. 为什么 ST 对"扎实的 plcopen"有结构性意义

没有 61131-3 语言层，用户用 C++ 摆弄 MC_* FB——心智模型是"库"；
有了 ST，用户写 `MC_MoveAbsolute(Axis := AxisX, Execute := TRUE, ...)`
——心智模型是"PLC"。这是 PLCopen 域从"合规的库"到"可信的运行时雏形"
的分水岭，也直接服务孪生（ST 程序在孪生里原样跑）与教学采纳。

## 2. 三档范围（各自独立可交付）

| 档 | 内容 | 分量 |
|----|------|------|
| **ST-0 逻辑子集** | 表达式/IF/CASE/FOR/WHILE、基本类型（BOOL/INT/DINT/REAL/LREAL/TIME）、VAR 声明、直接调用既有 FB 面（MC_*/基础 IEC FB）；扫描周期模型 | 中——一个批次可交付 |

## 3. 架构：编译到字节码的确定性 VM

```
ST 源码 ──[前端：递归下降解析 → 类型检查 → 字节码]──► 加载期（可分配）
字节码 + 静态内存镜像 ──[VM：解释执行]──► 扫描周期（RT 纪律域）
```

- **周期路径纪律沿用**：VM 执行零分配/无异常/有界（字节码长度即
  WCET 上界的度量基准）；全部内存在加载期由声明段静态铺好（IEC 的
  VAR 语义天然适合——PLC 本来就是静态内存模型）；
- 扫描模型：`st::Program::scan()` 与既有显式 `cycle()` 同构——用户
  executor 决定 ST 任务与运动周期的配比（同拍或降频任务）；
- FB 绑定：字节码 CALL 指令直达既有 C++ FB 门面（零胶水层——我们的
  FB 输入/输出本就是 POD 字段）；
- 调试钩子：字节码级行号表 + trace 环集成（X4 资产复用）。

## 4. 出处红线（决定自研前端）

MatIEC 为 GPL 系——按出处纪律**不评估、不参考其实现**；ST 文法规模
（约 60 条产生式）完全在自研递归下降范围内，且自研才能做到零分配
VM 与我们的 RT 纪律一体化。IEC 61131-3 文法结构为公开标准知识
（合规文档只引条目不抄文本，测试用例自造）。

## 5. 难点提要（详见 T30/T31）

IEC 隐式类型转换规则的完整语义（阴间但有限）；TIME 运算与我们整型
周期域的映射；VM 的 WCET 论证口径（每字节码指令有界 × 程序长度上界
= 用户责任 + 我们给度量工具）；标准函数库的验收矩阵（逐函数边界
用例）；ST-2 在线变更的状态迁移语义（远期，先声明不做）。
