## 1. 为什么 ST 对"扎实的 plcopen"有结构性意义

没有 61131-3 语言层，用户用 C++ 摆弄 MC_* FB——心智模型是"库"；
有了 ST，用户写 `MC_MoveAbsolute(Axis := AxisX, Execute := TRUE, ...)`
——心智模型是"PLC"。这是 PLCopen 域从"合规的库"到"可信的运行时雏形"
的分水岭，也直接服务孪生（ST 程序在孪生里原样跑）与教学采纳。

## 2. 三档范围（各自独立可交付）

| 档 | 内容 | 分量 |
|----|------|------|
| **ST-0 逻辑子集** | 表达式/IF/CASE/FOR/WHILE、基本类型（BOOL/INT/DINT/REAL/LREAL/TIME）、VAR 声明、直接调用既有 FB 面（MC_*/基础 IEC FB）；扫描周期模型 | 中——一个批次可交付 |
| **ST-1 完整语言** | STRUCT/ARRAY/枚举、FUNCTION/FUNCTION_BLOCK/PROGRAM POU、标准函数库（选择/比较/算术/字符串/时间）、多任务配置 | 大——多批次 |
| **ST-2 工程级** | 在线变更（online change）、调试器/断点/强制、符号监控 | 商业 PLC 领域——显式远期 |

## 3. 架构：编译到字节码的确定性 VM

```
ST 源码 ──[前端：递归下降解析 → 类型检查 → 字节码]──► 加载期（可分配）
字节码 + 静态内存镜像 ──[VM：解释执行]──► 扫描周期（RT 纪律域）
```

- **周期路径纪律沿用**：VM 执行零分配/无异常/有界（字节码长度即
  WCET 上界的度量基准）；全部内存在加载期由声明段静态铺好（IEC 的
  VAR 语义天然适合——PLC 本来就是静态内存模型）；
- 扫描模型：`st::Program::scan()` 与既有显式 `cycle()` 同构——用户
  executor 决定 ST 任务与运动周期的配比（同拍或降频任务）；
- FB 绑定：字节码 CALL 指令直达既有 C++ FB 门面（零胶水层——我们的
  FB 输入/输出本就是 POD 字段）；
- 调试钩子：字节码级行号表 + trace 环集成（X4 资产复用）。

## 4. 自研 vs MatIEC 裁决（2026-07-07，维护者问"完整级别 MatIEC 可用吗"）

**裁决：自研。** 三条理由：

1. **许可证结构性不可用**：MatIEC 是 GPL 转译器（IEC→C），生成代码
   依赖其 GPL 运行时头——生成物被沾染。fieldbus 的进程隔离招数在此
   失效：**总线是外设，语言是心脏**，GPL 边界放在心脏上等于把合规
   难题塞进每个用户的核心程序资产；
2. **架构失配**：其生成代码面向 Beremiz 运行时约定，与我们的周期
   纪律（零分配/无异常/整型周期 TIME/trace 一体）改造量不小于自研；
3. **成本论据已反转**：人力时代"自研完整语言层不可承受"是解锁门存在
   的原因；AI 吞吐实测（KB-034~051 节奏）下，规格外化 + 机读矩阵 +
   oracle 验收正是最佳地形——与 Part 1/2 的 45 块 FB 同种工程。

**MatIEC 的正确用法 = ADR-0003 模式（Ruckig 先例）**：只作**黑盒行为
oracle**——同一段 ST 程序双跑对照，不读其一行源码（运行 GPL 软件零
义务，出处零沾染），白得一个独立实现的语义裁判。此用法立 ADR 候补。

出处纪律重申：不评估、不参考其实现；IEC 61131-3 文法为公开标准知识
（合规文档只引条目不抄文本，测试用例自造）。

## 4.5 "完整级别"范围阶梯（维护者定调完整级后的口径）

ST 全量（ST-0→ST-1）→ **SFC 执行语义**（步/转换/动作/限定符的文本
形式运行时——图形编辑器另说，语义先行）→ 标准函数/FB 库全量（机读
矩阵驱动，T31）→ LD/FBD 随编辑器时代（语义下沉同一 VM）→ **IL 显式
不做**（Ed3 已弃用）→ ST-2 在线变更保持远期。

## 5. 难点提要（详见 T30/T31）

IEC 隐式类型转换规则的完整语义（阴间但有限）；TIME 运算与我们整型
周期域的映射；VM 的 WCET 论证口径（每字节码指令有界 × 程序长度上界
= 用户责任 + 我们给度量工具）；标准函数库的验收矩阵（逐函数边界
用例）；ST-2 在线变更的状态迁移语义（远期，先声明不做）。

## 6. 排位（2026-07-07 维护者裁决：选项 A，完整级入列）

语言层以 **L 系列**（L0-L7 + L∀ 验证贯穿）进入软件极致计划，为
PLCopen 扎实化收口后的下一里程碑主项；难点 T30-T39 已全量前置识别。
SFC 执行语义在列（L6，文本形式）；LD/FBD 图形层仍随层 4；IL 不做；
在线变更远期。
