# PLCOpen 库设计文档

> 状态：v0.x 基线参考。R4 切换后，默认架构入口是 [core/architecture.md](core/architecture.md)；本文只保留旧 `src/` 线的历史设计语境。

## 1. 概述

本文档描述了PLCOpen库的设计架构、实现细节和技术决策。PLCOpen库是一个C++库，实现了PLCopen运动控制标准（Part 1 & 2）中的功能块，旨在提供一个基础的PLC运动控制库，用于构建工业自动化和运动控制系统。

### 1.1 设计目标

- 提供符合PLCopen标准的运动控制功能块
- 实现与具体硬件无关的运动控制逻辑
- 提供清晰、灵活且可扩展的架构
- 支持多平台（Windows、Linux、macOS）
- 提供简单易用的API接口

### 1.2 开发背景

本项目基于PLCOpen运动控制标准，该标准由PLCOpen组织制定，旨在标准化不同供应商之间的运动控制功能块，使开发人员能够轻松在不同控制硬件上实现相同的功能。

## 2. 系统架构

### 2.1 整体架构

PLCOpen库采用了层次化的架构设计：

1. **功能块层（FB Layer）**：实现PLCOpen标准中定义的各种功能块
2. **运动控制层（Motion Control Layer）**：提供轴控制和运动规划的实现
3. **硬件抽象层（Hardware Abstraction Layer）**：抽象底层硬件接口，实现硬件无关性

```
+------------------------+
|    功能块层 (FB)        |
+------------------------+
|    运动控制层           |
+------------------------+
|    硬件抽象层           |
+------------------------+
```

### 2.2 模块结构

项目主要包含以下模块：

- **fb**：功能块的实现，包括单轴功能块和多轴功能块
- **motion**：运动控制模块，包括轴管理、调度器和插补控制
- **misc**：辅助功能模块，包括日志、错误处理等
- **demo**：示例代码，展示库的使用方法

```
plcopen/
├── src/
│   ├── fb/               # 功能块实现
│   ├── motion/           # 运动控制
│   │   ├── axis/         # 轴控制
│   │   └── interpolation/ # 插补控制
│   ├── misc/             # 辅助功能
│   └── demo/             # 示例代码
└── doc/
    ├── design/           # 设计文档
    ├── user_guide/       # 用户手册
    └── reference/        # 参考资料
```

## 3. 关键组件设计

### 3.1 功能块基类

所有功能块继承自`FunctionBlock`基类，该基类定义了功能块的基本接口和行为模式。功能块分为以下几类：

- `FbBaseType`：基本功能块类型
- `FbBasicType`：基础 IEC 非运动功能块类型
- `FbExecAxisType`：需要执行的轴功能块类型
- `FbExecAxisBufferType`：带缓冲模式的轴功能块类型
- `FbExecAxisBufferContSyncType`：主从同步类功能块类型
- `FbReadInfoAxisType`：读取轴信息的功能块类型
- `FbWriteInfoAxisType`：写入轴信息的功能块类型

```
FunctionBlock
├── FbBasicType
└── FbBaseType
    ├── FbExecAxisType
    │   └── FbExecAxisBufferType
    │       └── FbExecAxisBufferContSyncType
    ├── FbReadInfoAxisType
    └── FbWriteInfoAxisType
```

功能块继承结构的设计是为了最大程度地复用代码并确保功能块行为的一致性。所有功能块都遵循PLCOpen标准中定义的接口和行为。

### 3.2 轴控制系统

轴控制系统由以下组件组成：

- `Axis`：表示物理或虚拟轴的抽象，管理轴的状态和运动
- `Servo`：对伺服控制器的抽象，处理实际的运动控制
- `CamTable`：多轴 cam 跟随使用的主从位置映射表
- `Scheduler`：调度器，负责周期性推进轴的运动；功能块由调用方在每个 scan 中显式执行

轴控制系统负责管理轴的生命周期、状态转换和运动规划。它为功能块层提供了一个统一的接口，使功能块能够独立于具体硬件实现运动控制逻辑。

### 3.3 状态机设计

每个轴都有一个状态机，符合PLCOpen标准中定义的状态转换模型：

- `ErrorStop`：错误停止状态
- `Disabled`：禁用状态
- `Stopping`：停止中状态
- `Homing`：回原点状态
- `Standstill`：静止状态
- `DiscreteMotion`：离散运动状态
- `ContinuousMotion`：连续运动状态
- `SynchronizedMotion`：同步运动状态

状态转换逻辑遵循PLCOpen标准中定义的规则。状态机的实现使用了状态模式，每个状态都有自己的处理逻辑，使状态转换和处理更加清晰和可维护。

以下是轴状态机的简化表示：

```
         +-------------+
         | ErrorStop   |<---+
         +-------------+    |
             ^   |          |
             |   v          |
+--------+   | +-------------+
|Disabled|<->| | Stopping    |
+--------+   | +-------------+
    |        |      ^
    v        |      |
+--------+   |  +-------------+
|Standstill|<-   | Discrete   |
+--------+       | Motion     |
    |            +-------------+
    |                 ^
    v                 |
+--------+       +-------------+
| Homing |       | Continuous |
+--------+       | Motion     |
                 +-------------+
                      |
                      v
                 +-------------+
                 | Synchronized|
                 | Motion     |
                 +-------------+
```

### 3.4 运动规划

当前实现已经具备梯形与 jerk-aware 轨迹规划，并在此基础上补齐了单轴 motion、基础 IEC 块和最小多轴同步块。主要运动模式包括：

- 绝对位置运动（MoveAbsolute）
- 相对位置运动（MoveRelative）
- 叠加运动（MoveAdditive）
- 速度运动（MoveVelocity）

当前运动规划支持梯形与单轴 jerk-aware 轨迹，支持不同的缓冲模式（如 Aborting、Buffered 等）。运动规划算法考虑了以下因素：

- 最大速度限制
- 加速度和减速度限制
- 位置和速度平滑过渡
- 缓冲模式下的运动衔接

多轴 gear/cam 当前以单主单从的最小同步 runtime 落地，不包含完整 `AxesGroup` 框架。

### 3.5 错误处理

错误处理采用错误码机制，定义在`MC_ErrorCode`枚举中。功能块在执行过程中会检查各种条件，在发生错误时返回相应的错误码。

错误处理机制包括以下组件：

- 错误码定义（ErrorCode）
- 错误检测和报告
- 错误恢复机制（如Reset功能块）

每个功能块在执行操作前会执行参数检查，确保操作可以安全执行。当发生错误时，轴会进入ErrorStop状态，用户需要通过Reset功能块来恢复轴的正常工作状态。

## 4. 技术决策

### 4.1 使用C++17

选择C++17作为开发语言标准，利用其现代特性如结构化绑定、折叠表达式等，提高代码的可读性和效率。C++17还提供了更好的类型安全和更多的编译时检查，有助于减少运行时错误。

### 4.2 线程安全考虑

当前实现中，调度器采用单线程模型，由用户负责周期性调用`runCycle()`函数来推进系统状态。这种设计简化了线程安全问题，但在未来的版本中，我们计划提供多线程支持，允许在不同线程中同时执行不同的功能块。

### 4.3 跨平台支持

库设计时考虑了跨平台兼容性，通过CMake构建系统提供对Windows、Linux和macOS的支持。接口设计避免了平台特定的API，使用C++标准库和跨平台库来实现功能。

### 4.4 可扩展性设计

库的设计考虑了可扩展性，主要通过以下方面：

- 模块化架构：各模块之间通过明确的接口进行交互
- 接口抽象：硬件抽象层允许实现不同的硬件后端
- 功能块继承体系：便于添加新的功能块类型
- 配置灵活性：通过参数配置支持不同的运动控制需求

## 6. 开发规范

### 6.1 代码风格

项目采用了一致的代码风格，包括：

- 类名使用驼峰命名法（CamelCase）
- 方法和变量使用混合命名法（mixedCase）
- 成员变量以m前缀开头
- 使用4空格缩进
- 每行最大长度为120个字符

### 6.2 文档规范

代码文档使用以下规范：

- 文件头包含版权信息和许可证
- 类和方法有详细的文档注释
- 复杂算法包含实现说明
- 公共API提供完整的参数和返回值说明

### 6.3 测试策略

测试分为以下几类：

- 单元测试：测试各个功能块的独立功能
- 集成测试：测试多个功能块协同工作
- 系统测试：测试整个系统的功能
- 性能测试：测试系统在高负载下的性能

- **PLCOpen**：一个国际组织，致力于工业控制编程的标准化

- **状态机（State Machine）**：描述轴的状态和状态转换的模型
