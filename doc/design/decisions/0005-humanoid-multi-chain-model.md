# ADR-0005：人形多链执行模型（Accepted）

- 状态：**Accepted**（2026-07-06 维护者定调"按最优做、宇树级商业
  水准"裁决：按提案 (c) 落地，且关节协议升级为混合指令帧，见下）
- 背景难点：long-term-plan T16

## 问题

人形机器人是链树（躯干 → 双臂/双腿/头，20-48 关节），而 `AxisGroup`
是单链模型（MaxAxes=8、单 kinematics 插件、单共享路径）。人形执行
需要什么样的多链抽象？选错边界会把复杂度倒进所有上层。

## 选项

| 选项 | 内容 | 代价 |
|------|------|------|
| (a) 多组 + 组间协同原语 | 每链一个 group；补跨组帧同步、协同停、共享基座帧输入 | 全身一致性散落在协调层；组语义面膨胀可控 |
| (b) KinematicTree 一等公民 | 组升级为树结构，全身正逆解/全身命令原生支持 | 重写组语义，爆炸半径大；与"库"定位冲突（全身控制本属上层） |
| (c) 流域全身 + 组保持单链 | 人形执行走 H1 同步流帧（RL/全身控制器输出本就是全身关节帧），组只服务工业臂/龙门等单链 | 全身"运动语义"完全归上层——但这正是 robot-integration 定位（智能层之下的确定性关节执行层） |

## 裁决：**(c) 为主，(a) 按需渐进**

1. 人形主通道 = H1 同步关节流帧，且帧载荷按行业人形标准（宇树/MIT
   Cheetah 系）升级为**混合关节指令**：每关节每帧
   `{q_des, dq_des, τ_ff, Kp, Kd}`——位置/速度经滤波平滑升频，τ_ff 与
   增益作透传通道（同拍生效，不滤波不延迟）；上层全身控制器（RL/MPC）
   负责全身运动学与协调，库负责确定性执行与安全包络。**不做 (b)**：
   全身 IK/规划是上层学科，做进库里既违背定位又追不上学界迭代速度。
2. 单链组语义（位姿/笛卡尔/窗口）继续服务工业臂、龙门、SCARA——
   这是 PLCopen 语义的本乡。
3. (a) 的协同原语（跨组共享停车、共享基座帧输入 T17）等灯塔场景
   出现真实需求再立矩阵——避免为想象的房间装修。

## 后果

- 人形软件路线收敛到：H1 流帧 + T14 数值 IK（供上层调用或单链组用）
  + T15 动力学前馈 + T18 扭矩安全包络——全部是"执行层深化"，零架构
  重写；
- 库对人形的价值主张清晰化："你的策略每 1-10ms 给一帧全身混合指令，
  我保证它以 1-4kHz 确定性、平滑、带安全包络地到达每个关节"；
- 宇树级量化目标（进 H 系列验收）：48 关节混合帧 @1kHz 帧率、执行
  1-4kHz、帧→setpoint 延迟 ≤1 周期、τ_ff/增益透传零延迟、周期预算
  维持 <300µs@1kHz（交错口径）；
- 放弃的：库内全身逆解/步态——显式非目标。
