**前提假设**（用户已确认）：

## 1. 目标定义：什么叫「对标 Beckhoff / 西门子」

「对标」不是复刻。倍福 TwinCAT 是数百人年的平台；对一个开源项目，正确的目标是：**在选定的能力切面上达到同等的工程质量与可信度，并利用开源和可嵌入性形成差异化**。

### 1.1 对标锚点

| 对标物 | 能力面 | 阶段一（内核期，2026H2-2029） | 阶段二（平台期，2030+，条件触发) |
|--------|--------|------------------------------|----------------------------------|
| TwinCAT NC PTP | 单轴 PTP、主从耦合（gear/cam）、数百轴管理、1-2ms 周期 | **全面对标**（Part 1/2 已基本覆盖，差距在实时性证据与同步精度） | — |
| TwinCAT NC I | 3 路径轴 + 5 辅助轴插补、圆弧/样条、look-ahead、blending、DIN 66025 | **核心子集**：FB 驱动的路径运动（Part 4），不含 G-code 解释器 | G-code / DIN 66025 前端 |
| TwinCAT CNC (TF52xx) | 多通道 32 轴级完整 CNC | 不对标 | 不对标（明确放弃） |
| Siemens SIMOTION / SINUMERIK | 概念参照：IPO 双层结构、预处理/前瞻分离 | 借鉴架构，不对标产品 | — |
| CODESYS SoftMotion | PLCopen FB + 内核集成的软运动 | 功能面对标 | 运行时集成方式对标 |

### 1.2 「商用级」的可度量定义

达到以下全部指标，才允许对外声明「商用级」（阶段一 DoD）：

| # | 维度 | 硬指标 |
|---|------|--------|
| 1 | 实时确定性 | x86 + Linux PREEMPT_RT（6.12+ 主线）上：1ms 周期、8 协调轴 + 32 单轴，周期抖动 p99.999 < 50µs（72h 连续测试），运动周期路径**零堆分配、零阻塞锁** |
| 2 | 轨迹精度 | blending 公差带模式路径偏差 ≤ 用户公差；样条/圆弧速度波动 < 0.1%；cam 相位误差 < 1 个插补周期主轴位移 |
| 3 | 标准合规 | 取得 PLCopen Motion Control 认证（需 voting member 资格，自认证 + PLCopen 复核，3 年有效期） |
| 4 | 真实验证 | ≥3 家设备制造商产线部署 ≥12 个月，公开案例 ≥1 个 |
| 5 | 质量体系 | motion core 分支覆盖率 ≥85%；规划器 fuzz 测试；静态分析零 P0；确定性回放回归（黄金 setpoint 流对比） |
| 6 | 版本承诺 | v2.x LTS：24 个月缺陷维护 + SemVer ABI 承诺 |
| 7 | 文档 | 全 FB 参考、实时集成指南、调优指南、从 TwinCAT/CODESYS 的概念迁移指南 |
| 8 | 安全边界 | STO/SS1 集成边界文档化。**不做 SIL 认证**（永久非目标：认证绑定具体硬件与组织，属集成商责任） |

### 1.3 差异化立足点（为什么有人用我们而不是倍福）

1. **可嵌入**：作为库进入用户自己的运行时/操作系统/语言栈，不强加平台。倍福模式反过来。
2. **白盒**：算法可审计、可改。学术界与高端定制场景的刚需。
3. **仿真优先生态**：pyplcopen 数字孪生/离线验证路径，商业软件普遍薄弱。
4. **零授权费**：对量产设备成本敏感的中小设备商是硬吸引力。

### 1.4 机器人与人形机器人：范围决策（2026-07 补充，集成蓝图见 [robot-integration.md](robot-integration.md)）

2026 年机器人栈（尤其人形）的通行分层：上层智能（RL 策略 / MPC / 遥操作）以 50-500Hz 输出关节目标，下层以 1-4kHz 确定性环路做精插补、限幅、总线收发。**上层生态繁荣（开源框架众多），下层反而是每家在 SOEM/IgH 上重复手写的地方——恰好是本项目的能力面**。定位一句话：**不做机器人的大脑，做机器人的小脑与脊髓**（智能层之下、驱动器之上）。

| 能力 | 是否入库 | 说明 |
|------|----------|------|
| 关节空间 OTG（任意状态、jerk-limited） | ✅ 核心 | 即 6.4 算法栈层 1，与 PLC 场景完全复用 |
| 工业臂 kinematics（龙门/Delta/SCARA/球腕 6R 解析逆解） | ✅ Phase B2 | 工业机械臂本就是 Part 4 正统范围 |
| 轨迹流精插补 + 安全包络 | ✅ Phase B9（新增） | 接收上层策略/规划器的轨迹流，库内平滑、限幅、升频——人形落地的真实刚需 |
| CST 周期扭矩 + 全阶前馈钩子 | ✅ 强化现有 | 人形关节多为扭矩型驱动；`MC_TorqueControl` 已有雏形 |
| EtherCAT DC 确定性执行 | ✅ Phase B5/B7 | 人形整机主流总线选型 |
| 整机动力学 / WBC / MPC / 平衡控制 | ❌ 永不 | 另一个学科，已有 OCS2/crocoddyl 等生态；我们做它们的执行底座 |
| 浮动基座 / 接触规划 / RL 训练 | ❌ 永不 | 同上 |
| 感知 / 遥操作 | ❌ 永不 | — |

**商业逻辑**：机器人初创是 greenfield（无 CODESYS/倍福锁定）、以 C++ 团队为主（匹配「可嵌入库」形态）、融资密集（有付费能力），且这一层目前人人自研、无人开源做透。采用漏斗可能比传统设备商更快。风险（赛道波动）见第 7 章——缓解的关键是：机器人条目全部复用核心资产，无专用沉没成本。

### 1.5 用户怎么使用（目标用户与使用旅程）

| 用户 | 使用形态 | 典型旅程 |
|------|----------|----------|
| 设备制造商 C++ 团队 | 库嵌入自家控制器 | pyplcopen/demo 仿真验证方案 → C++ 按 FB API 写设备逻辑 → 实现 `Servo` 或直接用 `plcopen-fieldbus` 接 EtherCAT → PREEMPT_RT 参考 executor 部署 → trace 工具调优节拍 |
| 机器人公司（含人形） | 关节执行层 | 上层规划器/策略输出轨迹流 → B9 接口精插补 + 安全包络 → CSP/CST 出总线；臂类 PTP/直线用 kinematics 插件走标准 FB |
| 研究者 / 学生 | 仿真与教学 | pip 装 pyplcopen → 数字孪生 / 运动控制课程 → 带着熟悉度进产业（生态漏斗的入口） |
| PLC 工程师（Phase D 后） | ST / G-code 前端 | 条件触发后提供，非当前承诺 |

**采用漏斗**：仿真（零成本）→ 台架原型（低门槛）→ 产线（商用级承诺背书），与 Phase A/B/C 交付节奏一一对应。

**体验硬指标**（写进 DoD 的可测承诺）：clone 到第一条 S 曲线跑起来（仿真）≤ 30 分钟；开箱到真轴转动（fieldbus 配置器）≤ 1 天；同一套应用代码从仿真到真机**零修改**（`Servo` 抽象的核心价值）。

## 2. 差距分析（v0.10/v0.11 现状 → 阶段一终点）

现状基线：Part 1/2 合规矩阵 45/45 implemented（runtime boundary 显式声明）、AxesGroup foundation、v0.11 的 ACS 线性插补进行中；梯形 + 单轴 jerk-aware 规划；单线程调度器；无实时性声明；无总线层。

| 领域 | 现状 | 商用级要求 | 差距 |
|------|------|------------|------|
| 轨迹规划 | 单轴 jerk-aware S 曲线；组线性共享标量路径 | 任意状态间 OTG、多段 look-ahead、在线重规划语义完备 | **大** |
| 插补几何 | 直线（ACS） | 圆弧/螺旋/样条 + 弧长参数化 | **大** |
| 路径过渡 | BufferMode 速度阈值语义（30%/70%） | 公差带几何 blending（C1/C2 连续） | **大** |
| 坐标系 / kinematics | 仅 ACS | ACS/MCS/PCS、工具/工件补偿、kinematics 插件 | **大** |
| 实时性 | 用户负责 tick；无 jitter 证据 | RT 集成层 + 零分配审计 + 公开 jitter 基准 | **大** |
| 现场总线 | Servo 抽象（用户自接） | EtherCAT 参考适配（CiA402 + DC）、诊断 | **大** |
| 多轴同步 | gear/cam 单主单从、线性 cam 表 | 高阶 cam 曲线、主轴滤波、多从、相位管理 | 中 |
| 机器人关节执行 | `MC_TorqueControl` 透传；无轨迹流接口 | 轨迹流精插补 + 安全包络、CST 周期扭矩、6R 解析逆解 | 中 |
| 诊断工具 | 示波器 demo | 周期级 trace、录波格式、离线分析器 | 中 |
| 质量体系 | 覆盖率 >50%、CI、consumer 验证 | ≥85%、fuzz、回放回归、HIL 夜间回归 | 中 |
| 生态与信任 | README/examples/pyplcopen | 文档站、认证、灯塔案例、LTS | 中 |
| 单轴 FB 面 | Part 1/2 收口 | 同左 + 实时语义强化 | 小 |

结论：**单轴功能面已接近完整，真正的差距集中在「路径级运动 + 实时性证据 + 真实硬件闭环」三条线**。这就是阶段一的主战场。

## 4. 团队与资源缺口

### 4.3 资金缺口的诚实结论

### 4.4 单人 + AI 模式（2026-07 评估）

**结论：可行，但有三个硬前提**——全职（兼职 + AI 到不了商用级终点）、终点收窄（见下）、时间标定为 4.5-5.5 年。作为交换，现金需求从 600-1000 万级降到 100-200 万级（创始人工资自担 + 台架），**资金可行性大幅上升，代价是时间与单点风险**。

**AI 杠杆按工作类型严重不均**，这是整个评估的核心事实：

| 工作类型 | 占原计划 | AI 倍率 | 依据 |
|----------|----------|---------|------|
| 纯软件：算法/运行时/测试/移植/文档 | ~95 人月 | **2.5-3×** | 本项目规格外化程度极高（语义矩阵=规格、测试=验收、oracle=仲裁），是 AI 协作的最佳基质；OTG case 枚举、fuzz 基建、R3 移植、合规文档都是 AI 强项 |
| 硬件在环：EtherCAT 调驱、台架、抖动猎杀 | ~25 人月 | **1.2×** | AI 能读手册、分析日志、写调优脚本，但接线、示波器、物理迭代的墙钟时间不可压缩 |
| 信任与生态：灯塔支持、认证联络、社区 | ~20 人月 | **~1×** | 关系型工作；AI 可代写材料但不能代建信任 |

**换算**：全职单人 + AI，收窄终点后 ≈ 55-60 有效人月 ≈ **4.5-5.5 年到修订版 Phase C DoD**。微缩版证据就在本仓库：v0.x 的 45/45 矩阵、CI、覆盖率门禁就是单人兼职 + AI 协作产出的——但硬件墙和信任墙是 v0.x 历史尚未验证过的两类新工作。

**收窄版终点（solo-credible v2.0）**：

- 保留：核心重写 R0-R4 全部（干净架构对单人反而更重要——认知负载即产能）、验证基建（AI 杠杆的放大器，最不能省）、Tier 1/2 嵌入式、B9 机器人轨迹流（纯软件+廉价硬件可验证）、6R 解析逆解（纯软件）；
- 收窄：EtherCAT 只做 IgH 单栈、驱动器先适配 1 个品牌、台架 4 轴、灯塔用户 3 家 → 1 家；
- 延后：PLCopen 认证（费用+联络时间）、250µs 档、Phase D 全部。

**评审瓶颈是单人模式的真正约束**：AI 生成快于单人评审，而运动控制的未审代码是负债。解法已经内建在计划里——oracle/fuzz/回放把「逐行评审」转化为「评审验证系统 + 抽查」；补充三条纪律：AI 产出冷却 24h 后以 reviewer 身份自审；OTG 求解器与安全包络两个模块做一次性外部付费/学术审计；公开开发让社区眼球成为免费评审。

**AI 特有风险与既有对策的映射**：

| 风险 | 对策（多数已在计划内） |
|------|------------------------|
| 貌似正确的数值代码 | oracle + 百万级 fuzz 是硬门禁（6.4），不靠人眼 |
| 训练数据许可污染 | PROVENANCE 纪律与相似度抽查（rewrite-plan 3.6）显式覆盖 AI 输出 |
| 过度生成/范围蠕变 | 特性冻结清单 + 「代码量不是进度」写入反模式（6.6） |
| 长程一致性漂移 | 语义矩阵与设计文档作为单一事实源（既有方法论） |
| 维护者缺席 = 项目停摆 | 无解，只能缓解：公开开发、文档完备、关键决策记录——让项目「可被接手」 |

**回归团队模式的触发条件**：首个联合开发合同或外部资金到位 → 按 4.1 顺序补人（实时/驱动工程师优先），本节自动失效、回到主计划排期。单人 + AI 是**低现金启动路径**，不是终局形态。

## 5. 技术难点清单

按「问题本质 → 为什么难 → 业界做法 → 我们的策略」组织。难度：★（工程量）～★★★（存在开放性问题）。

### T1 周期内确定性（★★，Phase A，一切的地基）

**问题**：商用运动控制的第一承诺不是「快」，是「每个周期都一样快」。当前代码用 STL 容器与隐式分配，任何一次 `malloc`/页错误/锁竞争都可能造成周期超限。
**难点**：确定性是全局属性——99% 的代码合规没有意义，1 处违例即破功；且 C++ 的分配隐藏极深（`std::function`、`string`、容器扩容、异常路径）。
**业界做法**：预分配对象池 + 双缓冲命令交换（RT 线程与非 RT 线程间无锁 SPSC 队列）；TwinCAT/CODESYS 运行时均为静态内存模型。
**策略**：A2 建立「RT-safe 白名单」子集 + CI 静态扫描（禁分配、禁锁、禁系统调用）；规划（可分配）与插补（禁分配）在类型层面隔离；用 A6 基准框架持续测 p99.999 而非平均值。

### T2 Look-ahead 前瞻规划（★★★，Phase A v1 / Phase B v2，算法皇冠）

**问题**：数百个短路径段（激光切割/点胶场景每段 <1mm）下，逐段减速到零会把机器变成拖拉机。必须在整个前瞻窗口内求各段结点的最大可通过速度。
**难点**：
1. jerk 受限下「段末可达速度」不再有闭式解（梯形有 `v² = v₀² + 2as`，S 曲线没有对称式），可达性判定本身是小型优化问题；
2. 窗口滚动时的**重规划稳定性**——新段进入窗口导致此前决策改变，实现不当会产生速度振荡（规划抖动直接变成机械振动）；
3. 必须在周期预算内完成或可摊销、可中断。
**业界做法**：双向扫描（前向加速约束 + 后向减速约束取交），工业界普遍在梯形近似下做前瞻、执行层再做 jerk 平滑；TwinCAT NC I 的 look-ahead 覆盖全部已录入几何。
**策略**：v1 用梯形级双向扫描（保守但稳定，有成熟公开文献，专利风险低）；v2 引入 jerk 修正因子表（离线预计算可达速度修正曲线，避免在线解优化问题）；重规划只允许「单调收紧」（新信息只能降低结点速度上限，不能提高已承诺段的速度），以结构性手段消灭振荡。**这是效果与性能矛盾最尖锐的点，详见 6.3-#3 与 6.4 算法栈。**

### T3 几何 blending（★★，Phase A）

**问题**：现有 BufferMode 的 30%/70% 速度阈值语义是时间维的近似；商用级要求几何维的公差带过渡——拐角处插入过渡曲线，路径偏差 ≤ 用户给定公差，同时速度不必降零。
**难点**：过渡曲线要同时满足公差约束、曲率连续（否则加速度跳变）、参数化质量（劣质参数化会把误差转嫁给速度波动）；与 PLCopen `TransitionMode` 语义的映射要显式（标准给了模式枚举但没给几何定义，厂商各自解释）。
**业界做法**：圆角圆弧（C1）、双圆弧、五次 Bézier（C2）、clothoid（曲率线性）。
**策略**：见 6.3-#4 的选型矩阵；语义先行——先写 blending 语义矩阵（哪些 TransitionMode 组合支持、退化时降级到 BUFFERED 的规则），再写几何。现有速度阈值语义保留为兼容模式。

### T4 弧长参数化与样条插补（★★，Phase B）

**问题**：圆弧以外的曲线（样条）没有弧长的解析式。插补器需要「给定弧长 s → 参数 u」的稳定逆映射；误差直接表现为**速度波动**（进给率不稳 = 表面质量差）。
**难点**：数值积分精度、逆映射的实时求解、以及在曲率突变处的病态。
**业界做法**：规划期用自适应 Gauss-Legendre 积分建 s(u) 查找表，运行期查表 + 1-2 步牛顿修正，O(1) 且误差可控到 1e-8 相对量级。
**策略**：直接采用上述标准做法（规划期慢没关系，见 6.2 双层架构）；把「速度波动率 < 0.1%」写进 CI 效果基准。

### T5 Kinematics 插件框架（★★★，Phase B）

**问题**：坐标变换让库第一次要执行「第三方数学代码」在 RT 周期内。
**难点**：
1. 奇异点：逆解在奇异区数值爆炸（关节速度 → ∞），必须有阻尼策略（DLS）且行为可预测、可声明；
2. 双空间约束：笛卡尔空间限速 + 关节空间限速要**同时**满足——沿路径的时间缩放法（time-scaling）是正解，但与 look-ahead 耦合后复杂度上升；
3. 插件 ABI：第三方 kinematics 必须遵守 RT-safe 契约（无分配、有界迭代），需要 ABI 层面的约束和验证工具。
**策略**：解析解优先（参考实现只做有解析逆解的构型：龙门、Delta、SCARA）；数值逆解设硬上限（≤3 次牛顿迭代 + 上周期解热启动，超限报确定性错误而不是等收敛）；奇异区策略显式三选一（报错停机 / DLS 降级 + 路径偏差告警 / 禁入区预检查），默认预检查。6R 等复杂构型留给社区插件，核心库只保证框架与验证工具。

### T6 主从同步精度（★★，Phase B）

**问题**：gear/cam 从轴品质取决于主轴信号质量。用 actual position 驱动时，编码器量化噪声会被凸轮斜率放大；滤波又引入相位滞后——**噪声与滞后不可兼得**，这是同步类应用的核心矛盾。
**业界做法**：二阶跟踪滤波器（PLL 式 tracking loop）+ 速度前馈外推，把「滞后」转化为可补偿的确定相位，再做相位超前补偿；EtherCAT DC 时间戳用于把采样时刻对齐到统一时间轴。
**策略**：主轴信号处理做成显式可配置管线（raw / tracking filter / 外推階数），默认 tracking filter；效果指标「cam 相位误差 < 1 插补周期主轴位移」进 HIL 实测（B6）。虚拟主轴（virtual master）同步落地，绕开物理主轴噪声，是多数产线场景的更优解。

### T7 EtherCAT 与现场总线（★★，Phase B，工程量大 + 法律敏感）

**难点**：
1. DC 分布时钟：主站周期与 DC 时钟的相位锁定（Sync0 对齐），否则驱动器侧插值抖动；
2. CiA402 兼容矩阵：各厂商对象字典实现差异大（模式支持、单位、PDO 布局），需要按驱动器建兼容配置库——这是纯工程量但决定「开箱即用」体验；
3. 许可证：IgH master 内核模块 GPLv2（用户态库 LGPL）、SOEM v2 为 GPLv3/商业双许可。Apache 2.0 的核心库**不得静态耦合** GPL 代码。
**策略**：总线适配放独立仓库 `plcopen-fieldbus`，核心库只暴露 `Servo` + 时钟同步抽象；IgH 走 LGPL 用户态库动态链接，SOEM 适配器单独发布并声明其许可证后果，商用用户可自选商业授权栈（acontis 等）替换。ETG 会员（免费）在 B5 启动前完成。

### T8 数值鲁棒性（★，贯穿，容易被低估）

**问题清单**：
- 周期时间累积：`t += dt` 的浮点累积误差在 72h 运行后可达可观测量级 → 整型周期计数 × 周期时长，禁止浮点累加时间；
- 长距离运动的 double 精度分布：位置用绝对坐标累计 vs 段内相对坐标，后者精度友好；
- 退化几何：零长段、共线三点圆弧、半径 ≈ 弦长/2 的病态圆弧、公差大于段长的 blending——每种都要有显式语义（错误或降级），不能靠浮点巧合；
- 除法与开方的定义域保护要系统化而不是散落各处。
**策略**：A7 回放测试 + 规划器输入 fuzz（随机几何 + 极端参数），把数值边界当成合规矩阵的一部分维护。

### T9 在线重规划语义组合爆炸（★★，贯穿）

**问题**：override × ContinuousUpdate × BufferMode × blending × look-ahead 窗口，五个维度的组合语义在标准里没有完全定义，厂商实现互不一致。现有代码已在单轴维度收口（README 已知边界），路径维度会把组合数再乘一个量级。
**策略**：延续项目已被验证的方法论——**语义矩阵先行，实现跟随，未定义组合显式报错**。这是本项目相对商业闭源实现的文档优势，应保持。

### T10 API/ABI 稳定与认证证据链（★，Phase C）

PLCopen 认证是自认证 + 复核制：提交数据类型与 FB 支持表，成为 voting member 后申请，3 年有效需复审。**现有 compliance matrix 体系几乎就是认证申报表的雏形**，这是前期投入的直接回报。ABI 承诺（LTS）需要引入 ABI 检查工具（abi-compliance-checker）进 CI。

### T11 控制环边界决策（★，Phase B 前定案）

**问题**：跟随误差、前馈、振动抑制（input shaping）要不要入库？
**决策建议**：库的输出边界定为「setpoint 流 + 全阶前馈（pos/vel/acc/torque）」，位置环/速度环本体留在驱动侧（CiA402 CSP 模式的标准分工）。入库的只有：跟随误差**监控**（已有）、前馈**生成**、以及作为可选后处理的 setpoint 滤波（input shaping 属此类，Phase C 后评估）。理由：环路本体入库会把项目拖入伺服整定的泥潭，且与「可嵌入库」定位冲突。

### T12 RTCP / 刀尖点控制（★★★，两步走：机器人 TCP 在 B，加工级在 D）

**问题**：程序坐标以刀尖（TCP）表达，旋转轴运动时逐周期解算机床运动链（head-head / table-table / 混合构型），补偿直线轴使刀尖保持在编程路径上，进给率定义在刀尖路径上。西门子叫 TRAORI，海德汉/发那科叫 RTCP/TCPM。
**为什么难**：
1. 极点奇异：table-table AC 构型刀轴接近垂直时 C 轴不定，过极点需要专门策略（极点区检测、C 轴预定位/绕行），处理不当会出现旋转轴飞车；
2. 约束映射：刀尖空间的速度/加速度约束必须映射回关节空间才能进前瞻（复用 T5 时间缩放机制），映射的保守程度决定「敢跑多快」；
3. 姿态插补品质：刀轴方向的插补平滑性直接影响表面质量；
4. **验证成本**：加工级效果验证需要五轴机床或高保真仿真，超出现有台架预算量级。
**架构可行性**：新架构天然支持——kinematics 插件（B2）+ 周期内变换（几次矩阵乘，预算内）+ 前瞻约束映射（T5 机制复用）。**这不是能不能的问题，是验证手段与排期问题。**
**策略（两步走）**：
1. 机器人 TCP 先行（Phase B1 既有范围）：Part 4 的 PCS/工具坐标 + kinematics 插件即是「RTCP-lite」——同一套数学，现有台架可验证，直接服务机器人场景；
2. 加工级 RTCP 档（Phase D，灯塔触发）：依赖 D2 G-code 前端 + CNC 灯塔用户提供五轴验证手段；含极点策略与姿态插补品质指标（触发条件已入 Phase D 表）。

## 6. 性能与效果的平衡（算法专章）

### 6.1 总原则

1. **效果优先于峰值性能，确定性优先于平均性能**。运动控制的「性能」不是吞吐，是「在固定周期预算内可承诺的效果」。
2. **预算表方法论**：以 1ms 周期、主流工控机（x86，单核专用）为基线，周期内预算分配：

| 项 | 预算 | 说明 |
|----|------|------|
| 总线 I/O（帧收发 + PDO 映射） | 100µs | EtherCAT 1 帧往返 |
| 插补执行（8 协调轴 + 32 单轴） | 200µs | 查表 + 多项式求值级别的运算 |
| 规划摊销片（look-ahead 增量步） | 300µs | 可中断、可跨周期 |
| 用户逻辑（FB 调用等） | 300µs | 留给库使用者 |
| 安全余量 | 100µs | 吸收缓存/中断噪声 |

任何算法升级必须先回答：**落在哪一格预算里，超了挤谁**。

### 6.2 架构级平衡：双层结构（最重要的一条决策）

工业界通行做法（Siemens IPO/预处理分离、TwinCAT SAF/SVB 双任务）：

- **周期内层（插补器）**：每周期必须完成，只做 O(1) 工作——查表、多项式求值、状态推进。禁分配禁锁（T1）。
- **周期外层（规划器）**：look-ahead、blending 几何、弧长表构建、cam 表处理。异步或摊销执行，**慢了不影响运动平滑，只影响前瞻深度/新命令延迟**。

这个结构把大多数「性能 vs 效果」矛盾转化为**效果的软降级**：规划算力不足 → 前瞻窗口自动缩短 → 拐角速度保守 → 节拍变慢但运动永远平滑正确。这是比任何单点算法优化都值钱的架构性质，Phase A 必须落地。

### 6.3 权衡矩阵与推荐基线

| # | 决策点 | 效果优先方案 | 性能优先方案 | **推荐基线** | 升级触发 |
|---|--------|--------------|--------------|--------------|----------|
| 1 | 速度剖面 | snap-limited（4 阶） | 梯形（1 阶） | **7 段 jerk-limited S 曲线**：换 15-25% 单段时间，大幅降振动激励；snap 收益边际递减、参数辨识负担高 | 高速高惯量场景用户实证需要 snap |
| 2 | OTG 策略 | 每周期在线重解（Ruckig 式，任意状态→任意状态） | 事件驱动规划 + 周期采样 | **事件驱动为主**：仅在目标/override 变更时重规划（<10µs/周期采样成本）；在线 OTG 只用于变更瞬间的接管轨迹。注意 Ruckig 社区版（MIT）仅覆盖状态到状态，waypoints 属商业 Pro——自研规划器不依赖其 Pro 能力 | 高频目标流场景（视觉伺服）需求出现 |
| 3 | look-ahead 深度 | 1024 段全路径 | 32 段 | **128 段默认，可配 32-1024**：内存与重规划成本近似线性；小线段密集场景（点胶/激光）拐点通常在数百段；配合 6.2 摊销架构深度只影响 CPU 占比不影响正确性 | 灯塔用户的段密度画像 |
| 4 | blending 曲线 | clothoid（曲率线性，机床级） | 圆角圆弧（C1） | **五次 Bézier（C2，加速度连续）**：成本约为圆弧 3 倍但仍是闭式求值；clothoid 需数值积分（约 10 倍）且收益只在高速轮廓加工可感 | CNC 前端（Phase D）落地时重估 clothoid |
| 5 | 弧长参数化 | 自适应 Gauss 积分表 + 牛顿逆映射（1e-8） | 参数近似弦长（1e-3） | **前者**：贵的部分全在规划期（双层架构吸收），运行期 O(1)；1e-3 级近似会直接变成 0.1% 以上速度波动，不可接受 | 无需升级，一步到位 |
| 6 | cam 插值 | quintic（C2） | 线性（C0） | **存储层兼容线性表导入，运行层 quintic 段重建**：表内存约 3 倍、求值成本同数量级，换取加速度连续（从轴不敲齿）；C0 表保留为兼容模式并文档化其振动后果 | 无需升级 |
| 7 | 逆解精度 | 迭代至收敛 | 纯解析解 | **解析解族优先；数值解硬上限 3 次牛顿 + 热启动**：确定性 > 最后一微米精度；超限报错优于超时 | 复杂构型由插件自担 SLA |
| 8 | 主轴信号处理 | 观测器 + 外推超前补偿 | 原始信号直通 | **二阶跟踪滤波器默认 + 可配管线**（见 T6）：直通在真实编码器上不可用，重观测器参数整定负担高 | HIL 实测相位误差不达标 |
| 9 | 前馈阶次 | pos+vel+acc+torque 全阶 | 仅 pos | **库无条件生成全阶，用户按需接线**：生成成本可忽略（规划器副产品），效果差一个量级（每加一阶跟随误差约降一阶）；不接是用户的自由 | — |
| 10 | 周期档位 | 250µs | 2ms | **1ms 基线**；250µs 档位是 Phase C 目标且**只有在零分配 + 摊销架构验收后**才承诺 | 半导体/高速贴装类用户 |

### 6.4 最优加减速算法栈（四层，本章核心结论）

「最好的加减速效果」不是一个算法，是四层各司其职的栈。每层的可解性与参照：

| 层 | 内容 | 可解性 | 参照 |
|----|------|--------|------|
| 1. 状态到状态 OTG | 任意初始 (p,v,a)（含反向）→ 任意目标状态的时间最优 jerk-limited 轨迹，7 段闭式分段 | ✅ 已解，难在 case 枚举的工程量与数值边界 | Ruckig 社区版（MIT，可依赖或作交叉验证 oracle）、Reflexxes 谱系、公开文献 |
| 2. 前瞻结点调度 | 多段窗口内结点速度的双向扫描 + jerk 可达性修正 + 结点零加速度简化 | ✅ 工业级近似；距全局最优约几个百分点，**商业控制器发货的也是这个近似** | CNC feedrate scheduling 文献（见 T2） |
| 3. 几何限速 | 曲率 × 轴加速度上限（向心约束）、blending 公差带 | ✅ 已解 | 标准做法 |
| 4. 后置平滑（可选） | setpoint FIR 成形（一级 ≈ jerk 限制、两级级联 ≈ snap 限制）或 input shaping（ZV/ZVD）抑制已知机械谐振 | ✅ 已解；代价是固定群延迟，故设为 opt-in | Biagiotti & Melchiorri FIR 轨迹生成、input shaping 文献 |

**当前代码对照（2026-07 审计）**：`ProfilePlanner` 的 jerk 路径仅支持同向非零初速、零初始加速度，且以采样容器构造轨迹（同时违反 T1 零分配）。这正是 A9 的立项依据。**层 1 是杠杆最高的单项算法投资**——override 重规划、aborting 接管、blending 衔接、ContinuousUpdate 的运动品质全部直接受益；没有它，其余三层都在沙地上。

**验证策略**：闭式求解器唯一可靠的交付方式是「数值积分 oracle + 百万级随机初始状态 fuzz」对比（位置/速度/时间最优性三重断言），Ruckig 社区版可作第二 oracle 交叉验证。case 枚举类算法靠代码评审是审不出来的。

**明确不进基线**：snap-limited（4 阶）解析规划——时间损失继续上升而振动收益边际递减，参数辨识负担转嫁用户；需要时用层 4 双级 FIR 等效替代。

### 6.5 效果度量体系（没有度量就没有「效果」可言）

所有权衡决策必须有仪表盘支撑，进 CI 出趋势（A6/A7 框架承载）：

| 指标 | 定义 | 目标（阶段一终点） |
|------|------|--------------------|
| 路径误差 | 弦高偏差 / blending 公差利用率 | ≤ 用户公差，利用率 >80%（不过度保守） |
| 速度波动率 | 恒速段 σ(v)/v̄ | < 0.1% |
| 加速度连续性 | setpoint 二阶差分谱的高频能量 | S 曲线路径无阶跃 |
| 循环时间效率 | 实际段时间 / 理论时间最优 | > 90%（前瞻质量的直接度量） |
| 同步相位误差 | cam/gear 从轴相位差 | < 1 插补周期主轴位移 |
| 周期抖动 | p99.999 jitter（72h） | < 50µs @ 1ms 周期 |
| 规划延迟 | 命令到首个 setpoint | < 2 周期（事件驱动路径） |

**「循环时间效率」这一条特别值得强调**：它把「算法效果」翻译成了设备商听得懂的语言——节拍。前瞻算法每提升 1% 效率，对量产线就是真金白银，这是本项目算法投入的商业叙事。

### 6.6 反模式清单（写下来防止未来的自己）

- 过早 SIMD/并行化：在语义与回放测试稳定前做向量化，等于给 bug 上锁。
- 以平均延迟论英雄：运动控制只看尾延迟。
- 用双精度掩盖算法病态：精度问题先怀疑参数化/公式条件数，再怀疑字长。
- 为 benchmark 牺牲语义：任何「快但偶尔不对」的路径规划都是负资产。
- 在仿真里宣称效果：速度波动、相位误差必须有 HIL 实测背书（B6 的存在理由）。

### 6.7 关键指标可达性论证与反证点（2026-07 补充，回应评审疑虑）

**疑虑一：1ms 周期（p99.999 抖动 <50µs）真能达到吗？**

| 论据 | 内容 |
|------|------|
| 现状诚实 | **现在达不到，也没有任何证据**——v0.x 无 RT 声明、无基准。这正是 A6/R1 把基准 harness 排在一切声明之前的原因 |
| 存在性证明 | LinuxCNC 伺服线程 1kHz 在 PREEMPT_RT 上稳定服役多年（且是更老的硬件）；商用运行时在同级 x86 上以 50µs-1ms 周期出货多年；调优后（isolcpus、nohz_full、IRQ 绑核、关 SMT/C-states、mlockall）数十 µs 级尾延迟是公开可复现的常态 |
| 算力余量 | 插补是每轴 O(1) 闭式求值（数十 ns/轴），8+32 轴合计 µs 级，预算表留了 200µs——**瓶颈从来不是算术，是尾延迟** |
| 真正的风险 | 消费级主板的 SMI 中断、BIOS/固件行为、非 RT 核缓存干扰。对策是硬件选型清单 + 调优手册（B7 交付物），属工程而非算法风险 |
| 不承诺的 | Windows 实时、任意消费硬件、用户周期内阻塞代码 |
| **反证点** | R1 harness 上线后 4 周内在 NUC 级参考硬件出首份 72h 报告；若调优后守不住 100µs p99.999，公开数据并降级承诺到 2ms 档（按现有证据概率很低，但要给证伪留出口） |

**疑虑二：多轴算法的稳定性与效果靠什么保证？** 靠结构，不靠调参。

| 结构性保证 | 机制 |
|------------|------|
| 协调即构造 | 多轴由**单一路径参数**驱动（v0.11 已采用），成员轴在构造上不可能失同步；多轴稳定性被归约为 1-DOF 路径参数剖面问题——与单轴同一套数学 |
| 无迭代即无发散 | 双向扫描是一遍前向 + 一遍后向的链式约束传播，不是迭代求解器，不存在收敛性问题 |
| 单调收紧 | 已承诺窗口内结点速度上限只降不升（T2），振荡在构造上被排除而不是被阻尼 |
| 存在性证明 | GRBL 在 8 位 AVR 上以 ~16 段双向前瞻稳定服役十余年，LinuxCNC/Klipper 同族规划器久经考验；我们是在该结构上加 jerk 约束与效果提升——渐进强化，不是新科学 |
| 效果验收 | 6.5 指标（循环时间效率 >90%、速度波动 <0.1%、相位误差）+ B6 HIL 实测，不接受仿真自证 |

**疑虑三：RTCP 这类高级功能呢？** 见 T12——架构上可行（kinematics 插件 + 周期内变换 + T5 约束映射复用），真短板是五轴验证手段与排期；两步走：机器人 TCP 落 B1（台架可验证），加工级 RTCP 进 Phase D 灯塔触发。
