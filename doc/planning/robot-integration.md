## 1. 可行性结论（按机器人形态）

| 形态 | 可行性 | 路径 | 说明 |
|------|--------|------|------|
| 工业机械臂（6R / SCARA / Delta / 龙门） | ✅ **主线场景** | Phase B1-B3 + B2 kinematics 插件 | 这就是 PLCopen Part 4 的正统范围，与「给机床用」同一条路线，无额外范围 |
| 人形 / 腿足 / 研究平台（执行层） | ✅ **目标场景** | A9 OTG + B9 轨迹流 + B5 EtherCAT/CST | 上层智能输出目标流，本库做 1-4kHz 确定性执行（§2.1） |
| 协作臂（导纳 / 阻抗类交互） | ✅ 模式可行，环外实现 | superimposed 通道 + 扭矩前馈钩子 | 导纳修正量由用户算，经 `MC_MoveSuperimposed` / 流式偏移注入；阻抗环本体在驱动侧或用户侧（T11 边界） |
| AGV / AMR | ⚠️ 能用，不聚焦 | 现有速度/齿轮 FB | 轮组速度控制够用；导航栈与本库无关，不做适配投入 |
| 大脑层（WBC / MPC / RL / 平衡 / 感知） | ❌ 永不入库 | — | 已有 OCS2/crocoddyl/学习框架生态；我们是它们的执行底座 |

**结论：可行，且机器人场景不产生新范围**——所需能力全部已在计划内（A9 / B2 / B5 / B9），本文档只是把「怎么接」写清楚。

## 2. 两个参考架构

### 2.1 人形 / 研究机器人：策略驱动模式

```
 智能层(用户)                        本库（确定性执行层）                     硬件
┌─────────────┐  关节目标流    ┌──────────────────────────────────┐
│ RL 策略/MPC/ │  50-500Hz     │ B9 轨迹流接口                     │
│ 遥操作       │ ────────────▶ │  带时间戳环形缓冲(每关节)          │
└─────────────┘               │    ↓                              │   EtherCAT DC
┌─────────────┐               │ OTG 在线滤波(A9 求解器复用)        │   1-4kHz
│ 脚本/启动流程│  标准 FB      │    ↓                              │ ────────────▶ 关节
│ (归位/复位)  │ ────────────▶ │ 安全包络(位置/速度/加速度/扭矩钳位)│   CST+前馈
└─────────────┘               │    ↓                              │   (或 CSP)
                              │ L4 周期执行 → CiA402 模式管理(B5)  │
                              └──────────────────────────────────┘
```

四个关键机制：

1. **OTG 在线滤波模式（B9 的核心形态）**：每个周期以「当前状态 → 最新目标」重解一次 state-to-state 时间最优轨迹（复用 A9 求解器）。效果：策略输出天然被 jerk-limited 平滑、天然限幅、无 FIR 式固定相位滞后、目标跳变也不会产生冲击。**这正是机器人界今天用 Ruckig 社区版的方式**——我们的求解器同源同能力，且与下面三层在同一个确定性运行时里。
2. **断流看门狗**：目标流超时 → 先按衰减外推，再 OTG 受控停到零速。断流是软停不是急停，停车轨迹本身也 jerk-limited。
3. **模式管理（bumpless 切换）**：CSP↔CSV↔CST 切换时锁存当前状态、OTG 生成接管轨迹，位置零跳变；驱动侧模式切换语义属 B5 CiA402 状态机范围。
4. **脚本运动与策略运动同轴共存**：开机自检、归位、复位姿态走标准 PLCopen FB；策略接管时经同一命令生命周期（Aborting 语义）切换到流模式——两个世界共享一套状态机与安全包络，不是两套系统。

**规模量化**：28 关节 @ 1kHz CST 在 x86/ARM64 上远低于周期预算（OTG 采样是 O(1) 闭式求值）；每周期 28 次在线重解约数十 µs 量级，仍在预算内；2-4kHz 档位依赖 Phase C 性能收口（long-term-plan 6.3-#10）。

### 2.2 工业臂单元：标准 Part 4 模式

```
应用层(C++ / ROS 2 action / 后期 ST)
   → PLCopen FB：MC_MoveLinearAbsolute(PCS) / MC_MoveCircular / blending / look-ahead
   → B2 kinematics 插件（6R 解析逆解，球腕构型）
   → EtherCAT CSP @ 1-2kHz
力交互（打磨/装配）：力传感器 → 用户导纳算法 → MC_MoveSuperimposed 偏移通道
```

与机床路线完全共享 Phase B 的坐标系、前瞻、blending 投入——机器人臂对本库而言只是「多了一个 kinematics 插件的机床」。

## 5. 验证方式与效果指标

- **台架**：B6 台架增加一个机器人候选构型（二手桌面 6R 臂或 3 关节摆臂，预算增量约 ¥1-3 万，计入 long-term-plan 4.2 弹性）。
- **指标**（并入 6.5 效果度量体系）：流跟踪相位滞后 ≤ 2 个插补周期；断流受控停无超限；模式切换位置跳变 = 0；28 关节 @ 1kHz 周期预算占用 < 30%。
- **灯塔策略**：Phase B 的联合开发对象优先找一家机器人公司 + 一家传统设备商，两条采用漏斗同时验证（long-term-plan 8.2-#3 已更新）。

## 6. 诚实的风险

- **人形公司自研惯性**：这层他们已经手写过一遍，说服迁移需要「确定性证据 + 省人力」双重论证——所以 B7 的 72h 抖动报告和 B9 的开箱即用 demo 是销售材料，不只是工程交付。
- **速率军备**：部分人形关节走 2-4kHz 甚至专有总线；4kHz 承诺不能早于 Phase C 性能收口，谈客户时明说。
- **生态错位**：机器人界的默认语言是 ROS 2 + Python，不是 PLCopen FB；B9 接口设计必须让「不懂 PLCopen 的机器人工程师」十分钟看懂——接口命名向机器人惯例靠拢（stream/filter/envelope），PLCopen 语义作为底层而非门面暴露给这类用户。

## 6. 机器人面竞品对照（差异化第二张表，对应 1.3 的工业面）

| 对照物 | 它是什么 | 我们的差异 |
|--------|---------|-----------|
| 宇树/厂商 SDK | 绑定自家硬件的关节接口 | 开源、跨驱动品牌（EtherCAT/CiA402）、同协议形态（混合指令帧） |
| ros2_control | 控制器插件框架（管道，不带算法） | 我们自带确定性 OTG/滤波/安全包络与认证级验证纪律；无 ROS 依赖可嵌入；未来可作 ros2_control 后端（门控候选） |
| Ruckig | OTG 单点（社区版功能受限） | 我们是完整执行层：流语义、安全包络、组/坐标、总线路径、证据体系 |
| mc_rtc / OCS2 / Crocoddyl | 全身控制/MPC（上层） | **互补非竞品**——它们正是 ADR-0005 里"上层"的典型住户，是集成目标不是对手 |
| LinuxCNC | CNC 控制器 | 服务不同世界（G-code 门控中）；我们的前瞻为 jerk 精确级 |

差异化一句话（机器人面）：**"策略之下、电机之上"的开源确定性执行层
——带认证级验证纪律的那一个。**

## 7. 人形安全标准边界（声明）

本库不声明符合 ISO 13482（服务机器人）/ISO/TS 15066（协作机器人）
等安全标准——功能安全认证绑定整机与组织，属集成商责任（与 1.2 #8
STO/SS1 口径一致）。库提供的是**安全语义构件**：安全包络、协同停、
扭矩三层监督（T18）、故障统一框架（T20），并在文档中说明它们与上述
标准条款的对应关系（材料性说明，非合规声明）。
