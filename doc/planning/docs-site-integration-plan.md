# 项目文档站内整合计划

> 状态：2026-07-24 已批准实施。用户要求继续把其他文档页整合进双语站点。

## 1. 最可能调整的决定

### 公开信息架构

```text
首页
├─ 快速开始
├─ 使用指南
├─ 参考
├─ 项目文档
│  ├─ 状态与方向
│  ├─ 架构
│  ├─ 合规与已知边界
│  └─ 贡献、治理、安全、变更日志
└─ 版本
```

- **置信度：高**
- 当前导航中七个 GitHub 直链改为双语站内页；另增加状态与方向、项目导览。
- 站内页负责导读与稳定上下文，时效性事实和规范原文继续回链权威仓库文档。
- **会推翻此决定的证据**：维护者要求完整复制全部工程文档，或要求把内部规划
  和归档作为普通用户导航。

### 整合边界

- `doc/planning/`、`doc/archive/`、`doc/vision/` 与逐条合规矩阵不进入主导航。
- Doxygen C++ API 继续保持唯一 `/api/` 入口。
- **置信度：高**
- **会推翻此决定的证据**：这些材料有明确的外部用户任务，且能定义不会误导
  当前能力的稳定入口。

## 2. 假设

- “整合”指让公开项目主题在官网内可浏览，而不是把所有 Markdown 无差别发布。
  置信度高，来源：现有导航和文档分层。
- 中英文站继续保持相同页面路径。置信度高，来源：既有双语合同。
- 权威工程文档大多为中文，因此英文站采用忠实摘要并回链原文，而不制造第二份
  规范。置信度高，来源：仓库现状。

## 3. 偏离策略

- 遇到内容频繁变化时，选择稳定导读与权威链接，不复制时效性长表。
- 遇到内部证据有用户价值时，只从对应公开主题页提供深链，不扩大主导航。
- 只有需要新增依赖、改变公开 URL、暴露敏感报告流程或复制规范形成双重事实源
  时停止并重新确认。

## 4. 机械工作（低评审价值）

- 增加九对 `project/` 中英文页面。
- 重组两套 MkDocs 导航和首页链接。
- 扩展双语验证器，锁定页面、导航、权威源回链与嵌套 index 路径。
- 更新 Changelog、规划索引和实施记录。

## 5. 验证

- 新契约在实现前明确失败，实现后通过。
- 中英文 MkDocs 分别 strict 构建。
- 21 对 Markdown 页面均有对应 HTML、canonical、语言切换和 sitemap 项。
- 所有生成 HTML 的站内目标与片段有效。
- 项目主题导航不再直接跳转到 GitHub；每个站内页仍可到达权威来源。
- PR Documentation workflow 与合并后的 Pages 部署通过，公网中英文深层页为
  HTTP 200。
