# H1：迷你人形载体计划（plcopen dogfood 平台）

> 状态：**维护者已定向（2026-07-12）**——定位 = plcopen 载体，预算档
> = ¥3k–5k 迷你级，两步走（迷你级验证后再议 Berkeley Lite 级）。
> 本文是 H 方向（2026-07-11 拍板时挂触发器）的首个触发事件的执行计划。
> 硬件采购为人专属动作；软件线全部走既有门禁与语义矩阵流程。

## 1. 定位（一句话）

用 ¥3–5k 造一台 45cm 级开源迷你人形，**所有运动软件由 plcopen 内核
驱动**：总线 adapter → MC FB → cam/路径表步态 → ST 语言直驱——它是
内核的活体展示、文档站首页素材、以及 LeRobot 生态的接触点。

## 2. 诚实边界（先于一切承诺）

| 边界 | 事实 |
|------|------|
| 步态天花板 | STS3215 只有位置模式（无力矩控制）→ 只能准静态步态（慢走/挥臂/舞步表），做不出跑跳。真·动态行走归 Berkeley Lite 级（RL 策略，非 PLCopen FB 地盘）——那是第二步的事，且届时 plcopen 的角色是上肢/执行器桥，不是步态生成器 |
| 总线速率 | TTL 半双工串行 1Mbps，16-20 舵机轮询 ≈ 50–100Hz 周期档——不是 EtherCAT 1kHz。CycleConfig 按实际周期声明，不虚标 |
| 部署平台 | 真机跑 RPi/Linux；Windows 串口延迟仅限开发环境 |

## 3. 硬件路线

**机械设计消费上游开源项目 Zeroth-01**（kscalelabs/zeroth-bot，MIT，
未归档，最后推送 2026-04）：只取 STL/CAD + 结构 BOM，**其软件栈一概
不用**（我们的价值主张就是换成 plcopen 栈）。打印件不入本仓库，引用
上游 commit hash 记录版本；若后续需要修改结构件再按 vendoring 流程
（plcopen-provenance）带 LICENSE 落 `third_party/`。

**舵机选型即战略**：飞特 STS3215 与 SO-ARM101（已购）同款——一个
Feetech 总线 adapter 同时服务机械臂与人形两台设备。

## 4. 软件工作流（AI 全量承担，硬件到货前即可开工）

| # | 批次 | 内容 | 依赖 | 流程 |
|---|------|------|------|------|
| S1 | adapter 矩阵 | Feetech STS 总线 adapter 语义矩阵：Servo 窄接口（ADR-0004）映射、位置模式/扭矩开关/回读寄存器、周期档与丢帧语义、多舵机轮询调度 | 飞特官方协议手册（公开） | 矩阵 → **人批** |
| S2 | adapter 实现 | `core/adapters/` 新增 + ServoSim 联调 + 协议帧黄金测试（纯软件，无硬件依赖） | S1 批准 | 测试先行 + 门禁 |
| S3 | 上肢管线 | pyplcopen 暴露 + PoseArmSim/6R 已有资产复用，MuJoCo 孪生先行（挥手/指向 demo） | S2 | 既有回放门禁 |
| S4 | 步态表 | 步态 = cam 规律/路径表回放（Part 4 path_table + cam 资产的天然映射），MuJoCo 里先走通 | S3 | 声明变更流程 |
| S5 | 真机落地 | 标定/回零（**Part 5 homing FB 直接派上用场**）→ 真机复现 S3/S4 | 硬件到货 + S4 | 真机证据归档 |
| S6 | 生态接口 | 文档站 demo 素材；LeRobot 数据集格式互通评估（录制我们驱动的轨迹供 RL 用） | S5 | 文档同提交 |

ST 语言直驱（L2a 之后）：`MC_MoveAbsolute` 由 ST 程序发出、驱动真机
挥手——这是文档站首页想要的那张图。

## 5. 与既有计划的关系

- **不挤占 L 系列主线**：S1/S2 是 adapters 层（既有 Servo 窄接口的
  第二个实现，CiA402 之后），属并行/穿插项性质；L 系列批次照常。
- **PLCopen 对照线（P-AUDIT）归 Codex**，本计划不触碰
  `doc/compliance/plcopen-*`。
- Berkeley Lite（¥2.3万级，真·RL 行走）为第二步候选，**迷你级收口
  后再议**——届时迷你级的 adapter/管线/步态表资产全部可迁移。
