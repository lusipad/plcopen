**审计的直接推论**：

1. **换 MIT 不需要全部重写**。只需清理这 302 行所在的代码路径（清单已有），加上对「结构性衍生」的保守处理（规划器与 Axis 生命周期是重点），即可获得干净的 relicense 权利。
2. **重写的真实理由必须是架构，不是许可证**。恰好，架构理由是成立的（见 §1）。
3. i5cnc 是 Apache 2.0：即使什么都不做，现状也完全合法合规；这件事没有时间压力。

## 1. 为什么重写（以及为什么现在）

### 1.1 站得住的理由：现架构与商用级目标的四个根本冲突

| # | 现状 | 目标（long-term-plan） | 为什么增量改造 ≈ 重写 |
|---|------|------------------------|----------------------|
| 1 | 分配散布各处（规划器 `samples.push_back` 采样式构造、容器扩容、裸 `new Servo()`） | 周期路径零堆分配、零锁（A2/T1） | 零分配是全局属性，逐文件改造要触碰每一处热路径 |
| 2 | 规划即插补的单层结构 | 规划/插补双层硬边界（6.2 节，商用架构的核心） | 这是骨架级变更，旧代码没有这个骨架 |
| 3 | FB 直连轴对象、公有可变成员、裸指针所有权、隐式共享状态 | 单写者数据流、可快照运行时、确定性回放 | 所有权模型是贯穿性设计，无法局部替换 |
| 4 | 路径不是一等公民（blending 是 30%/70% 速度阈值补丁） | 路径段缓冲 + 前瞻 + 几何 blending 为核心（A3-A5） | 在旧骨架上挂路径缓冲等于先重写骨架 |

**关键判断**：原 Phase A（30 人月）本来就要动到核心的每一处——它实质上是一次伪装成增量的重写。把它显式化为重写，多花的是移植成本，买到的是干净骨架 + 干净出处（provenance）。

### 1.2 为什么敢重写（大爆炸重写的坟场里我们的不同点）

经典教训（Netscape 式重写失败）成立的前提是：代码量大、隐性知识多、语义没有外化。本项目相反：

- 核心仅 ~12.5k 行，且刚完成全面审计；
- **语义已经外化成可执行规格**：45/45 合规矩阵 + 全量 Catch2 测试 + 已知边界文档——重写最怕的「忘掉旧代码处理过的边角」，这些边角就在测试里；
- 单维护者决策链，没有组织摩擦。

### 1.3 红线：重写 ≠ 重新发明

以下资产**原样保留**，它们才是两年积累的真正价值：

- FB 公开命名与语义（45/45 矩阵作为新核的**验收规格**）；
- 已知边界语义（如 `MC_SetOverride` 作用范围、queued handoff 规则）默认不变，故意变更须单独立项说明；
- 全部 Catch2 测试（移植为新核验收，测试先行）；
- 文档体系与「语义矩阵先行」方法论；
- `pyplcopen` 公开 API 面。

## 2. 目标架构

### 2.1 分层与依赖规则

```
        ┌────────────────────────────────────────────────┐
  L7    │ adapters: servo-sim / fieldbus(独立仓库) /      │  外圈可脏
        │ rt-executor / python / trace 工具               │
        ├────────────────────────────────────────────────┤
  L6    │ fb/    PLCopen FB 门面（Execute/Done/Busy 契约）│  薄
  L5    │ axis/  轴&组状态机、命令生命周期、BufferMode    │
        ├────────────────────────────────────────────────┤
  L4    │ exec/  周期执行：插补采样、gear/cam 同步、叠加  │  RT：零分配
  L3    │ plan/  前瞻规划：路径缓冲、双向扫描、blending   │  非 RT：摊销
  L2    │ geom/  段几何：line/arc/spline、弧长参数化      │  纯值语义
  L1    │ otg/   单 DOF 时间最优 jerk-limited 求解器      │  纯函数
  L0    │ rt/    周期时间域、静态容器、SPSC、错误码、trace│  无依赖
        └────────────────────────────────────────────────┘
```

**依赖规则**：只向内（向下）依赖。**L0-L4 不知道 PLCopen 的存在**——它们是通用运动内核，可独立复用；`otg/` 甚至可以单独发布（对标 Ruckig 社区版的生态位）。PLCopen 语义全部收在 L5/L6。机器人轨迹流模式（long-term-plan 1.4/B9）= L3 的另一个生产者，新架构里天然入位。

### 2.2 数据流：单写者管线

```
 用户线程(任意)          周期边界              规划域(摊销/异步)         RT 插补域
┌──────────┐  SPSC   ┌──────────┐         ┌──────────────┐  承诺轨迹  ┌──────────┐
│ FB 门面   │ ──────▶ │ 命令接收  │ ──────▶ │ 前瞻/blending │ ────────▶ │ 周期采样  │──▶ Servo
│ (L6)     │  队列    │ (L5)     │         │ (L3)          │  环形缓冲  │ (L4)     │
└──────────┘         └──────────┘         └──────────────┘           └──────────┘
      ▲                                                                    │
      └────────────── 状态快照（seqlock 双缓冲，无锁回读） ◀───────────────┘
```

每一块状态**恰好一个写入上下文**；跨域只通过两种结构：SPSC 队列（命令去程）与 seqlock 快照（状态回程）。这直接消灭现架构里 FB 与轴对象共享可变状态带来的整类竞态与测试不可复现问题。

### 2.3 八条核心决策（每条都是对旧架构病灶的否定）

| # | 决策 | 内容 | 否定的旧病灶 |
|---|------|------|--------------|
| D1 | **configure → freeze → run 生命周期** | 轴数/组数/队列深/前瞻窗全部前置声明；`freeze()` 后零分配，分配器 hook 断言守卫 | 运行中隐式分配 |
| D2 | **时间 = 整型周期计数** | 物理时间只在边界换算；规划输出以 tick 为单位 | `t += dt` 浮点累积（T8） |
| D3 | **RT 路径无异常、无 RTTI、无系统调用** | 错误码 + `Result<T>` 风格；可 `-fno-exceptions` 构建 | 隐式异常路径 |
| D4 | **内层零开销多态，边界窄虚接口** | L0-L4 用 C++20 concepts/模板；只有 Servo/Kinematics/TraceSink 是虚接口（每轴每周期一次调用，成本可接受，换 ABI 稳定） | 到处虚函数或到处模板的两个极端 |
| D5 | **运行时是值** | 整个运行时状态可快照、可序列化 → 确定性回放、数字孪生、断点续测都是副产品 | 隐藏全局状态 |
| D6 | **核心永不碰 OS** | 用户（或参考 executor）拥有线程与时钟；仿真=虚拟时间下调 `cycle()`，仿真与真机同构 | —（这是现架构做对的一点，保留并强化） |
| D7 | **观测性内建** | 编译期可关的 trace 点从第一天进核心；二进制录波格式 v1 与内核同步设计 | 事后补观测（改造成本极高） |
| D8 | **C++20** | concepts、`span`、designated initializers；MSVC 2022 / GCC 10+ / Clang 10+ 全覆盖 | C++17 的接口约束表达力不足 |

### 2.4 关键接口速写（定基调，非最终签名）

```cpp
// L1 otg/ —— 纯函数，无状态，可百万级 fuzz（对标 6.4 算法栈层 1）
struct State1D  { double p, v, a; };
struct Limits1D { double vMax, aMax, dMax, jMax; };
class  Profile1D { /* ≤7 段闭式分段多项式，定长存储，无堆 */ };

Result<Profile1D> plan(State1D from, Target1D to, Limits1D lim); // 任意初始态(含反向)，时间最优
State1D sample(const Profile1D&, CycleTick t);                   // O(1) 求值，RT 安全
```

```cpp
// L5/L6 —— 容量前置 + 冻结；FB 是薄门面
plcopen::Runtime rt(Config{ .axes = 8, .groups = 1, .lookahead = 128, .cycle = 1ms });
rt.freeze();                        // 此后零分配；违例在 debug 构建直接断言

// RT 线程（用户拥有）：
rt.cycle(io.inputs(), io.outputs()); // 严格 O(1)，WCET 可标定

// 任意线程：
FbMoveAbsolute move{rt.axis(1)};     // 门面只做命令封装 + 快照读取
```

### 2.5 仓库与版本策略

- **同仓重写**，不开新仓：保留 star/issue/CI/搜索权重。新核在 `core/` 树内生长，旧 `src/` 保持可构建直到切换日，切换后删除并归档 tag。
- **不改名、不换品牌**：重写期任何品牌动作都是范围蠕变。
- 版本纪元：新核以 `v1.0.0-alpha` 起（旧线停在 v0.x），对外信号清晰：v0.x = 旧架构维护线，v1 = 新内核。

### 2.6 许可证决策 D-LIC（需要你拍板，建议放到评审会）

| 方案 | 得 | 失 | 法务动作 |
|------|----|----|----------|
| **A. 保持 Apache 2.0**（推荐） | 显式**专利授权条款**——运动控制是专利密集领域（blending/前瞻厂商专利多），Apache 2.0 同时保护用户和项目不被贡献者反咬；工业界采购法务最熟悉；**零迁移动作** | 比 MIT 略「重」的观感 | 无 |
| B. 换 MIT | 更短更「友好」；机器人生态惯例（Ruckig/多数机器人库为 MIT/BSD），对 1.4 机器人受众有亲和力 | **放弃专利条款**；已发布的 v0.x 无法撤回 Apache（只影响未来版本） | 清理 302 行 i5 残留 + 结构性衍生保守处理；`PROVENANCE.md` 记录；NOTICE 迁移 |
| C. 双许可 Apache 2.0 OR MIT（Rust 生态惯例） | 用户自选，两边好处兼得 | 维护两份声明的轻微成本 | 同 B |

**建议**：如果换许可证的动机是「对机器人社区更友好」，方案 C 以极小成本达成；如果动机只是「摆脱 i5」，审计已证明**不需要**为此改许可证。无论选哪个，重写本身按清洁室纪律执行（§3.7），出处干净是副产品。

### 2.7 嵌入式设备支持（分级承诺，2026-07 补充）

新架构的八条决策（尤其 D1 零分配、D3 无异常/无 RTTI、D6 核心不碰 OS）恰好就是 MCU 固件的约束集——**嵌入式兼容是重写的副产品，不是额外目标**。按目标分三档：

| 档位 | 目标 | 可行性 | 承诺 |
|------|------|--------|------|
| Tier 1 | 嵌入式 Linux（ARM64 Cortex-A：i.MX8/RK3588/TI Sitara/树莓派 + PREEMPT_RT） | **现在就可行**（本质是小型工控机；PREEMPT_RT 主线支持 ARM64） | 正式支持：R1 起 CI 增加 ARM64 交叉编译 + QEMU 测试，Phase B HIL 台架含一块 ARM 板 |
| Tier 2 | RTOS/MCU，双精度 FPU（Cortex-M7/M85、R5F @ ≥300MHz，FreeRTOS/Zephyr/裸机） | **新核可行，旧核不可行**（旧核 STL 动态分配/异常；新核 L0-L4 + L5/L6 子集按 `Config` 缩容即可） | 构建档支持：`-fno-exceptions -fno-rtti` + 交叉编译 CI + footprint 门禁进 R1；MCU 参考 demo（如 STM32H7 双轴）列 Phase B 机会项（P2） |
| Tier 3 | 单精度 FPU（Cortex-M4）、DSP（C2000）、无 FPU | 不承诺（double 软浮点慢 10-20×；float 标量模板会翻倍测试矩阵且伤精度口径；C2000 工具链无 C++20） | 范围外；未来如有真实需求，走 C ABI 边界评估 |

**Tier 2 的量化边界**（R1 footprint 门禁实证前为估算）：2-4 轴、32 段前瞻窗、1-4kHz 插补周期；RAM 数十 KB 级（OTG profile <1KB/轴、前瞻段 ~300B/段）、Flash 200-400KB；look-ahead 走低优先级任务摊销（双层架构在 RTOS 上同样成立）。总线侧 MCU 场景通常不跑 EtherCAT 主站，`Servo` 抽象直接对接本地 step/dir、PWM 或电流环。

**纪律**：嵌入式支持不得反向驱动核心设计超出 RT 已有约束——它是免费搭车，就让它保持免费。守住的手段是 R1 的交叉编译 CI（防止 `<thread>`/分配这类依赖悄悄爬进核心）+ 每 PR footprint 报告。

**12 个月终点的诚实定义**：交付新内核 v1.0-alpha + 1ms 证据（72h 报告）+ 完整验证体系 + Tier 1/2 构建证据。**不含**：EtherCAT 真机、kinematics、坐标系、认证、灯塔用户、商用级声明——这些是第 13 个月起的 Phase B（真机闭环优先），按 long-term-plan 相对时间触发。

**压缩排期的三条纪律**：

1. 范围是唯一变量：任何年中新想法一律进 backlog，不进当年计划——12 个月计划死于第 7 个月的「顺便」；
2. 超期砍 stretch 不砍验证：R3 是最可能超期段（语义对齐的长尾），缓冲已含在 M11-12；
3. 全职是承重墙：若实际投入回落到兼职 10-15h/周，同范围自动展开为 ~3 年，**不做中间假设**。

### 3.2 顺序背后的逻辑

L0/L1 最先，因为它们**可以在旧系统还活着的时候独立交付价值**：otg/ 求解器是纯函数库，写完即可单独测试、单独发布、甚至先给旧核当第二 oracle 用。风险最高的移植（R3）放在新内核已经稳定之后，用旧测试套件当安全网。每个 R 阶段结束都有可运行、可演示的产物——绞杀者模式的本质：**任何时刻项目都没有「拆到一半」的状态**。

### 3.3 回放语料：切换的仲裁者

R0 录制的语料 = 旧引擎在全量测试场景下的逐周期 setpoint 流。R3/R4 的合并门禁：

- 语义**未**声明变更的场景：新旧输出逐周期 diff，差异即缺陷（浮点容差 1e-12 相对）；
- 语义**已**声明变更的场景（如 blending 从速度阈值换成公差带）：diff 报告人工审签 + 写入迁移说明。

### 3.4 旧线维护政策（「抛弃」的确切含义）

抛弃 ≠ 删除。v0.x 维护分支规则：**只修 P0 缺陷，为期 6 个月（至 2027Q1），不加任何功能**。理由：(a) 已有下游 consumer 不断供；(b) 回放基线需要旧引擎持续可构建；(c) 双轨开发功能是重写失败的第一死因，用规则堵死。

### 3.5 对外沟通

重写期最大的软风险是「项目看起来停滞了」。对策：把重写本身做成传播素材——公开 rewrite RFC（本文档脱敏版）、每月进度笔记、otg/ 子库先行发布。开源项目「公开地重写」比「悄悄地重写」存活率高得多。

### 3.6 文档与架构图整合（M0 内执行，约 1-2 天）

重写决策使现有文档间出现了真实矛盾（ROADMAP 的里程碑机制 vs 12 个月冲刺、VISION 的「暂不做 RT-PREEMPT」vs 新计划以 PREEMPT_RT 为中心、README 的 v0.x 架构图 vs 新 L0-L7 架构）。整合分三拍，**只有第一拍在 M0 立即执行**：

**第一拍（M0，战略层收敛）**：

| 文档 | 动作 |
|------|------|
| `ROADMAP.md` | 「当前里程碑」替换为 12 个月冲刺指针（本文档 3.1b）；季度复盘机制与里程碑历史保留 |

**第三拍（R4，切换收口）**：README 全面改写为新核并承载唯一架构图（ASCII，与仓库风格一致，不引入绘图工具链）；旧设计文档移入 `doc/design/v0/`；CHANGELOG 写版本纪元说明。

### 3.7 清洁室纪律（如选 MIT/双许可）

- 新核编写时**不打开旧核心文件对照抄写**；语义来源限定为：合规矩阵、测试、已知边界文档、PLCopen 标准文本；
- §0 清单中的 18 个文件（尤其 `ProfilePlanner.cpp` / `AxisMove.cpp` / `Axis.cpp`）为重点回避对象；
- `PROVENANCE.md` 记录每个模块的语义来源；R4 收口时对新核跑一次与旧核的相似度抽查（作为自查证据，非法律保证）。

## 5. Definition of Done（R4 切换判据）

1. 移植后的全量 Catch2 绿，覆盖率 ≥ 旧核基线（>50%，目标 70%+ 起步）；
2. 回放语料 diff 报告审签：未声明变更场景零差异，声明变更场景有迁移说明；
3. 基准：1ms 周期 8 协调轴 + 32 单轴，新核周期耗时 ≤ 旧核 50%（闭式求值对采样式的预期优势），`freeze()` 后分配断言 72h 零触发；
4. `find_package` / `FetchContent` consumer 在新核上通过；pyplcopen smoke 通过；
5. 迁移指南（旧→新 API 变更表）+ `PROVENANCE.md` + LICENSE/NOTICE 状态与 D-LIC 决策一致；
6. v0.x EOL 时间表公告发布。
