# Z 系列收口计划

## 1. 目标与完成定义

本批一次收口 `Z0`～`Z5`、`Z0′` 与 `Z3′`。已经有远端发布或门禁证据的
批次只复核事实，不重复实现；审计确认仍有缺口的 `Z0`～`Z5` 以仓库内可执行
证据闭合。

- `Z0` / `Z0′`：保留已完成的首轮证据，并建立每次 T/Z 收口都必须登记的
  冷用户清单；公开入口实跑不得借用源码树或 `PYTHONPATH`。
- `Z1`：PyPI 三平台 wheel 保持可用，并补齐可无交互执行的“五分钟数字孪生”
  notebook 及 CI 门。
- `Z2`：在现有 `CycleConfig` 上补齐最小轴/组 SI 配置结构、C++/Python 入口，
  验证两个周期档换算后产生等价物理行为。
- `Z3` / `Z3′`：Python、C++、ST 三条 30 分钟旅程均有唯一主路径，示例可执行，
  文档站严格构建通过；算法白盒保留为参考页。
- `Z4`：仓库提供可运行的 Conan `test_package` 与 vcpkg overlay port，并在 CI
  验证真实消费者。中央 registry 的外部 PR、CI 和审核状态单独登记，不把
  “可提交”写成“已收录”。
- `Z5`：稳定 `ErrorCode` 文本保持不变，新增逐码排障提示和 Python 薄绑定；
  现有 `PLCT v1` 周期 trace 可生成自包含 HTML 图表，无新增运行时依赖。

## 2. 关键决策

1. 三条入门旅程采用 Python / C++ / ST。理由是当前采纳入口和 Z3′ 的后续
   计划均明确要求 ST；算法页属于深入参考，不占第三条主旅程。
2. `ErrorCode` 不改数值、不改 `to_string()` 精确字符串。排障提示放在新的
   非周期诊断元数据层，避免破坏 ABI、ST `ErrorID` 映射与下游字符串匹配。
3. Z5 可视化消费已有 executor `PLCT v1` 文件，不把 ST 调试器内部记录冻结为
   跨工具格式，也不引入 rerun。在线示波器仍属于后续 D3。
4. Z4 的完成事实拆成两层：本仓配方和消费者门禁可以本批完成；ConanCenter /
   vcpkg curated registry 必须等待外部维护者审核，状态只能写成待提交或审核中。

置信度：高。会推翻本计划的条件只有：现有公开包不再可用、包管理器当前规范
要求与无依赖/header-only 形态冲突，或实现需要改变实时周期语义。

## 3. 实施顺序与验证

1. 先加失败测试：轴/组 SI 配置、全 `ErrorCode` 提示覆盖、未知码回退、PLCT
   HTML 输出、Conan 消费者和 vcpkg overlay 消费者。
2. 最小实现轴/组配置、诊断元数据与 trace HTML；验证定向 C++、Python 和工具单测。
3. 增加 notebook 与 ST 主旅程及其可执行示例；同步 C++/Python 主路径和
   MkDocs 导航，并让 notebook/三条旅程都由 CI 消费同源内容。
4. 完成 Conan/vcpkg 配方和 CI 接线；本机可用工具实测，缺失工具由 CI 配置与
   静态合同测试补证，不伪造执行结果。
5. 补齐 Z0 持续登记模板并完成本批公开入口冷用户实跑记录。
6. 对齐 README、STATUS、ROADMAP、CHANGELOG 与本实施记录。
7. 运行相关 CTest、全量非 fuzz、文档 strict build、消费者门及独立审查。

## 4. 偏差纪律

- 不新增依赖，不修改运动或 ST 周期语义，不扩展 D1～D3 产品范围。
- 所有新工具只读用户明确传入的 trace，并只写用户明确指定的输出文件。
- 若第三个实质偏差出现，或必须改变公开 ABI/语义矩阵，停止实现并重新诊断。
- 中央 registry 的账号、外部 PR 审核和最终收录不作为本地代码“绿灯”的替代品。
