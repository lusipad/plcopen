## 当前事实基线（2026-07-05 本地核对）

- R0-R4 重写冲刺软件面已收口：v0.x FB 面与 pyplcopen 面全量由新核承接，全量 CTest 26 项通过，黄金回放回归上线，core 合并行覆盖 85.37%。剩余 R4.8（EOL 公告）/ R4.9（`v1.0.0-alpha` 发布）为人工项，不阻塞 Phase B 软件开发。
- DoD §5.3 对照门禁 **PASS**（legacy 43ms / core 4ms = 0.093）：此前"新核规划成本 15×"系 `set_power` 每周期 abort 缺陷的误归因，已修复（见 r4-evidence-package.md 复测节）。`plan_time_optimal` 单次 ~5-10µs，满足事件驱动规划与 B9 每周期在线重解的预算。
- 新核能力面：A9 OTG v1（零边界加速度全状态域 + 非零初始加速度）、A3 圆弧 v1、A4 公差带 blending v1、A5 前瞻 v1（含圆弧切向直通）、gear/cam/combine 同步、superimposed、组 FB 面。
- 尚无：坐标系栈（仅 ACS）、kinematics、轨迹流接口、cam 高阶曲线、EtherCAT、真机证据。

## 拆分规则

沿用 `r0-r4-work-breakdown.md`：一个任务 = 一个 issue / 小 PR；有前置、DoD、最小验证命令；风险分级 T0-T3 沿用 `ai-collaboration.md`。追加两条：

- **语义矩阵先行**：每个批次的第一个任务是规格文档（`doc/compliance/`），规格获人批准前不写实现（CLAUDE.md 硬规则 1）。
- **纯软件判据**：任务的 DoD 必须可在无真实伺服/总线的环境下自动化验证（单元测试、oracle、fuzz、回放、pyplcopen 仿真）。需要真铁的验收指标一律进「硬件延后清单」，不冒充已验证。

## 批次排序与理由

```
BS1 B9 轨迹流（机器人模式）   ← 首批：只依赖 A9 OTG（已交付），纯软件可验证闭环，
                                 机器人是重点服务对象（long-term-plan 1.4）
BS2 B1 坐标系栈              ← 规格先行批次，Part 4 坐标语义矩阵需人批；是 B2 的前置
BS3 B2 kinematics 插件       ← 依赖 BS2 的 MCS/ACS 概念；参考实现全部解析解，纯软件
BS4 B3 look-ahead v2         ← 依赖 A5 v1 既有窗口；jerk 受限结点可达性
BS5 B4 cam 高阶化            ← 独立于 BS2-BS4，可作穿插缓冲任务
BS6 B5 纯软件面              ← Servo 适配器 ADR 裁决 + CiA402 状态机纯软件仿真
```

B1 语义矩阵（BS2.1）可与 BS1 实现并行起草——规格评审的人工等待期正好被 BS1 的实现吞吐填充。

## BS1：B9 轨迹流接口（机器人模式）——**已完成（2026-07-05）**

目标：上层策略/规划器输出 50-500Hz 关节目标流，库内 OTG 在线滤波升频到周期级 + 安全包络 + 断流看门狗。接口命名向机器人惯例靠拢（stream / filter / envelope），PLCopen 语义作底层（robot-integration §6）。

> 状态：BS1.1-BS1.9 全部落库（KB-034/KB-035），出口判据全部满足：相位滞后 ≤2 周期、
