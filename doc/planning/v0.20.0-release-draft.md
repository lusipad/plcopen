## 发布形式

### 1. GitHub Release（主发布页）

- 普通 0.x 版本：`v0.20.0`，发布后标记为 Latest，不标记 prerelease；
  “非 prerelease”不等于 1.0 稳定性承诺。
- C++ 交付：GitHub 自动生成的 source `.zip` / `.tar.gz`，其中包含
  C++17 header-only 新核、CMake install/export、Conan recipe 与消费示例。
- 不附加 Windows/Linux/macOS 的 C++ 二进制安装器。header-only 库没有
  必要制造平台二进制矩阵，源码包才是可复现、可审计的交付物。
- vcpkg 清单仍是草稿，Conan recipe 仍需用户从源码创建；本次不宣称已进入
  vcpkg/ConanCenter 公共仓库。

### 2. PyPI（Python 消费入口）

- 包：`pyplcopen==0.20.0`。
- 资产：CPython 3.10～3.13 的 Windows、manylinux x86_64、macOS x86_64/
  arm64 wheels，以及一个 sdist。
- tag 推送触发 `.github/workflows/wheels.yml`，通过 Trusted Publishing/OIDC
  发布，不保存长期 PyPI token。
- 前置条件：维护者先在 PyPI 注册 `pyplcopen` trusted publisher，并在
  GitHub 仓库创建 `pypi` environment。两项未完成时不得推 tag，否则构建
  可以成功但发布作业会失败。

### 3. 文档站

- 文档继续发布到 <http://lusipad.com/plcopen/>。
- Release notes 链接 STATUS、CHANGELOG、迁移指南、已知边界和商用证据总账；
  不复制另一套容易漂移的能力说明。

## Release notes 草稿

### 这版是什么

`v0.20.0` 是新 `core/` 成为默认消费面后的首个正式 0.x 检查点。它把
PLCopen Part 1/4/5 软件合同、确定性 ST 语言层、时间最优运动规划、轨迹执行、
kinematics/坐标系/流接口和 Python 仿真入口装进同一个可复验版本。它适合
评估、集成和仿真，不是完整 PLC 平台，也不是经过 PLCopen 或 Safety 认证的
工业控制器。

### 主要变化

- PLCopen Part 1/2 软件语义缺口 D-01～D-20 已关闭；Part 4 达到 68/68
  同名 C++ 门面；Part 5 达到 11/11 标准 FB 与 45 B + 102 E 机读声明。
- IEC 61131-3 ST 运动导向声明集完成 L0～L7 与 L∀：134 个标准 FB、1476 个
  pin 全部接入 native adapter，feature-set `pending=0`。
- 新核覆盖单轴/组运动、笛卡尔插补、blending/look-ahead、gear/cam、
  kinematics、B9 轨迹流、CiA402/Feetech 纯软件 adapter 与双域 executor。
- 严格浮点合同、18 份逐周期黄金回放、RT 静态扫描、分支覆盖、变异测试、
  ARM64/QEMU、TSAN 与独立 Nightly fuzz 已接入门禁。
- 日常 Linux CI 不再运行 fuzz，fuzz 只在 Core Nightly 执行；全量
  `clang-tidy` 维持 8 路并行，保留检查面同时缩短反馈时间。
- Python 绑定提供 AxisSim、PoseArmSim、轨迹流和 cam 工具，发布候选构建
  三平台 wheels 与 sdist。

### 兼容性与边界

- 版本仍小于 1.0，不承诺 ABI 稳定；公开 API 变化按 SemVer 记录，但在 1.0
  前仍允许经过 CHANGELOG 与迁移说明的破坏性调整。
- 旧 `src/` v0.11 线保持 P0-only 冻结，仅作黄金回放与迁移基线；默认
  `plcopen::plcopen`、demo、consumer 与 Python 绑定均指向新核。
- 不包含完整 PLC IDE、全部 IEC 61131-3 语言、EtherCAT 产品化、Safety
  功能、PLCopen 认证或真机 72h 实时声明。
- Feetech adapter 当前是无 IO 的协议层与 Sim；动态单位和部分 Status 位未
  经官方资料/真机核验，不得直接进入机器。

完整明细见 [CHANGELOG](../../CHANGELOG.md)，现状与限制见
[STATUS](../../STATUS.md) 和[已知边界](../compliance/known-boundaries.md)。

## 人工发布检查单

1. 审阅本草案、CHANGELOG 和版本成熟度边界。
2. 在 PyPI 创建/确认 `pyplcopen` 项目 Trusted Publisher：owner `lusipad`、
   repository `plcopen`、workflow `wheels.yml`、environment `pypi`。
3. 在 GitHub 仓库创建 `pypi` environment；无需配置 API token secret。
4. 确认发布候选 commit 的全部门禁为绿。
5. 在该 commit 创建并推送 annotated tag `v0.20.0`。
6. 等待 tag 触发的 Wheels 与 PyPI publish 成功，下载并验证 wheel/sdist。
7. 创建 GitHub Release，粘贴本页 Release notes，标记 Latest。
8. 发布后把本页、STATUS 与 ROADMAP 的状态从“候选”更新为“已发布”。

发布 tag、PyPI publisher 注册和 GitHub Release 属维护者对外动作；AI 只准备
提交、验证证据与可粘贴文案。
