# PLCopen / Beckhoff 能力对等收束计划

> 决策日期：2026-07-16。本文把“先收束 PLCopen，并与 Beckhoff 能力
> 对等”转换成可验收的工程边界；执行优先级以根目录 `ROADMAP.md` 为准。

## 1. 对等口径

目标锚点是 Beckhoff `Tc2_MC2` 与 `Tc3_McCoordinatedMotion` 的**核心可编程
运动能力和运行语义**，不是复刻 TwinCAT 产品平台。验收面是本项目默认
C++ 公共 FB/API、逐周期状态机、错误合同和可重复验证证据。

纳入范围：

- 单轴 PTP、回零、停止/接管、override、状态与参数回读；
- gear、cam、同步相位、touch probe、飞剪类主从耦合；
- 轴组生命周期、线性/圆弧/路径运动、blending、look-ahead；
- ACS/MCS/PCS 坐标变换、工具/载荷、点动、动态坐标跟踪；
- axis↔group 同步、输送带/转台跟踪及对应中止/错误传播；
- 无堆分配周期路径、确定性回放、ARM64/x86 跨平台门禁和公开语义文档。

明确排除：

- TwinCAT IDE、可视化配置器、在线调试器和工程文件兼容；
- EtherCAT 主站/驱动产品化、Safety 实现或认证；
- CNC/G-code/DIN 66025、多通道 CNC；
- XPlanar、碰撞避免、液压、完整机器人动力学等独立产品族；
- 以轴数、品牌私有参数或 UI 数量做机械式数字对齐。

ST 编译器不是本收束批的验收面；但 PLCopen 引脚合同继续保持机读化，后续
ST 绑定只能消费同一合同，不能形成第二套 FB 语义。

## 2. “能力对等”的完成定义

每项能力必须同时满足以下条件，才可标记为关闭：

1. 有稳定的公开入口；底层字段或多个 FB 的手工组合不算同等能力。
2. 输入、输出、上升沿/电平、Busy/Active/Done/Aborted/Error 生命周期有明确合同。
3. 非法参数、前置条件失败、接管和中止保持原子性，不留下半提交状态。
4. 周期路径不分配、不阻塞；输出状态始终有限且可回放。
5. 至少有正常、边界、错误、接管四类测试；适合随机化的入口有确定性 fuzz。
6. Windows、Linux GCC/Clang、ARM64 和静态门禁通过；覆盖率不低于现行硬门。
7. 权威矩阵与实现同批更新，所有子集和未支持项如实登记。

“能力对等”不等于 PLCopen 官方认证，也不等于真实硬件性能对拍。认证、
1 ms 真机抖动和 Beckhoff 黑盒 benchmark 仍分别受会员/台架/EULA 门控。

## 3. 收束序列

| 门 | 内容 | 出口证据 |
|---|---|---|
| C0 | 恢复主线质量门 | Windows 全测、Linux GCC/Clang、ARM64、clang-tidy、RT scan、coverage 全绿 |
| C1 | 固化 P4-B2 | 工具/载荷/ACS-MCS-PCS Jog 合同、fuzz 与文档落库 |
| C2 | Part 4 功能补齐 | 动态坐标、跟踪、axis↔group 同步、刚体动态及其真实消费路径 |
| C3 | Part 4 门面补齐 | 68/68 同名公共门面；逐项 B/E/O 与状态机证据，不以别名冒充 |
| C4 | Part 1/2 语义清零 | D-01~D-20 全部关闭；B 级引脚、BufferMode/接管/回读合同一致 |
| C5 | Part 5 收口 | 11/11 不只“有门面”，而是标准派生类型、I/O 和可软件验证语义闭合 |
| C6 | 对等验收 | 能力矩阵逐项标记 implemented/partial/excluded，迁移指南与限制注册表一致 |

顺序是硬约束：先恢复证据门，再增加能力；任何新实现不得用降低门禁、扩大
容差或把错误改成静默降级来换取通过。
