不得创建或推送 tag，也不得创建 GitHub Release。

## 版本判断

本轮采用 `v0.21.0`，不采用 `v0.20.1`：

- `v0.20.0..main` 包含 H1/H2/H3、T2a/T2b、D1/D3、Z1～Z5、X5、
  Y4b/Y7b1/Y7b2a 等新增能力，不是只修复既有版本缺陷的补丁批；
- 未发现把当前版本推进到 1.0 的新证据。稳定 ABI、真实硬件长期验证、
  PLCopen/Safety 认证、灯塔用户与维护周期承诺仍未形成；
- `v1.0.0-alpha` 继续保留为历史实验性预览，不删除、不改写。

## 发布形式

### GitHub Release

- 普通 0.x 版本：`v0.21.0`，发布后标记为 Latest，不标记 prerelease；
- C++ 继续以 GitHub 自动生成的 source `.zip` / `.tar.gz` 交付，其中包含
  C++17 header-only 内核、CMake install/export、本地 Conan recipe、示例与
  文档；
- 不新增独立 C++ 平台安装器或共享库二进制。

### PyPI

- 包：`pyplcopen==0.21.0`；
- `v*` tag 触发 `.github/workflows/wheels.yml`，构建 CPython 3.10～3.13 的
  Windows、manylinux x86_64、macOS x86_64/arm64 wheels 与一个 sdist；
- 只有 tag push 才执行 Trusted Publishing/OIDC 发布。候选阶段只手动构建
  wheels/sdist，`publish_pypi` 必须按条件跳过；
- 现有 `pypi` environment 与 Trusted Publisher 沿用 `v0.20.0` 已验证配置。

### C++ 包管理器边界

- 根 `.version`、CMake、Conan recipe 与 vcpkg manifest 跟随源码更新到
  `0.21.0`；
- `packaging/conan-center/` 与 `ports/plcopen/` 是中央 registry 提交资产，
  当前仍固定已公开且有真实归档哈希的 `v0.20.0`。tag 尚不存在时不得伪造
  `v0.21.0` URL 或哈希；正式 tag 可下载并核验后，再以独立提交新增版本。

### 文档与工具

- 面向用户的 GitHub Release body 使用
  [`docs/releases/v0.21.0.md`](../../docs/releases/v0.21.0.md)，中文镜像为
  [`docs.zh/releases/v0.21.0.md`](../../docs.zh/releases/v0.21.0.md)；
- D1 ST Language Server 随 Python 源码/包进入本版本；VS Code 扩展仍只形成
  可复验的本地 VSIX/CI artifact，不声明已发布到 Marketplace；
- 文档继续发布到 <https://lusipad.com/plcopen/> 与 `/en/` 英文镜像。

## 发布执行顺序

1. 对齐版本元数据、CHANGELOG、双语 Release body、公开入口与本检查单。
2. 运行本地版本一致性、sdist、Debug build、全量 CTest、RT scan、replay、
   双语 MkDocs strict 与链接检查。
3. 提交并推送候选分支，通过 Windows、Linux、Language Tools、Twin 与
   Documentation PR 门禁。
4. 在同一候选提交手动运行 Wheels、Core Nightly、Coverage Gate 与
   Mutation Score Gate；记录 run URL 与关键指标。
5. 全部门禁绿色后合入 `main`，确认最终目标提交的主线门禁。
6. 维护者明确指定“发布 `v0.21.0`，目标 `<full SHA>`”后，创建并推送
   annotated tag。
7. 等待 tag Wheels/PyPI 作业完成，公开下载 wheel/sdist 并校验包版本与哈希。
8. 使用 `docs/releases/v0.21.0.md` 创建 GitHub Release，标记 Latest、
   非 prerelease。
9. 运行公开冷用户安装/消费复验，再把 README、STATUS、ROADMAP、本页和
   文档站更新为“已发布”。

发布 tag / GitHub Release 需要维护者明确指定版本与目标提交；
LICENSE/NOTICE/PROVENANCE、账号、签署、法务与外部承诺仍只由人落地。
