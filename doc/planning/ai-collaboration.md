# AI-First 工程体系改造方案（2026-07 提案）

## 本文档的性质

| 是什么 | 不是什么 |
|--------|----------|
| 把「大部分编码/测试/文档由 AI 接手」变成工程体系的改造清单 | 对某个 AI 工具的绑定（工单化后任何 agent 可执行） |
| long-term-plan 4.4（单人+AI 模式）的操作化 | 新增排期（绝大部分并入 M0/R1，净增 3-5 天） |

**分工定义**：人 = 方向、规格审批、T2 评审、硬件、发布与法务、社区；AI = 实现、测试、文档、脚本、调查的第一稿到第 N 稿。**AI 接手的是工作量，不是判断。**

---

## 1. 总原则：门禁代替信任

AI 产出不靠「相信它写对了」进主干，靠**机器可判定的门禁**。人评审只聚焦门禁覆盖不到的地方（架构、语义裁决、安全边界）。

推论：验证基建（oracle / fuzz / 回放 / 基准 / 零分配断言）从「质量工具」升格为 **AI 吞吐的放大器**——门禁越硬，可安全授予 AI 的自主权越大，人评审带宽越省。这就是 R1 排在一切之前的第二重理由。

**门禁全家桶**（R1 起逐步点亮，全部红灯即拒合）：

| 门禁 | 判定内容 |
|------|----------|
| build 矩阵 | Windows/Linux/ARM64 交叉编译全绿 |
| 测试 | 全量 Catch2 + 覆盖率地板（新核 ≥70% 起步，目标 85%） |
| 回放 diff | 规划器/执行器变更必须过黄金语料对比（未声明变更 = 零差异） |
| fuzz smoke | PR 内秒级随机状态冒烟；夜间小时级深度 fuzz |
| 基准门 | 周期耗时 / 抖动 / 效果指标（循环时间效率、速度波动）无回归 |
| RT-safety | cycle-path 目录静态扫描：禁分配/锁/异常/系统调用/浮点时间累加 |
| docs-sync | 公开头文件或合规矩阵变更必须伴随文档变更 |
| 格式 | clang-format 强制（AI diff 干净的前提） |

## 2. 六个工作流的改造

### 2.1 规格层：从「人读的文档」到「机读的规格」

- 合规矩阵增加**机读源**（YAML：FB 名、IO、语义条目、测试锚点 ID、边界声明），markdown 表由脚本生成——单一事实源，AI 与 CI 消费同一份数据；
- 「已知边界」逐条编号（KB-001…），测试用例引用编号——AI 改动时可精确检索受影响边界，人可用编号下达工单；
- **语义矩阵先行**方法论不变且升级为流程：新特性 = 先提交规格/矩阵 PR（人审，小而快），再放 AI 实现（大而自动）。

### 2.2 代码层：让仓库可导航、可局部理解

- 每模块（新核 L0-L7 目录）配 README：职责、公开契约、不变量、RT 约束、禁止事项——AI 会话的模块级上下文入口，随 R1-R3 建层时同步写；
- 层级依赖只向内 + 小文件 + 稳定公开头：AI 无需全局上下文即可安全改局部；
- 命名/错误码规范成文一次，此后由格式与评审执行。

### 2.3 测试层：AI 的主战场，但要防「假测试」

- 测试先行（写规格化测试 → 实现使其通过）；property-based + oracle + 回放为主力形态；
- **变异测试（mutation testing）抽查**：AI 写的测试可能恒真——用变异分数抽查测试有效性，这是 AI-First 特有的质量风险，人写测试时代可以不设防，现在必须设防；
- 覆盖率只当地板不当目标（防刷指标）。

### 2.4 文档层：文档即上下文

- 文档与代码**同 PR 强制**（docs-sync 门禁）——过期文档在 AI 时代是主动负债：AI 每次会话都会读取并放大错误上下文；
- 文档分层图（doc/planning/README.md）保持单一事实源；矛盾即 bug，按 bug 处理；
- CHANGELOG 条目由 PR 模板强制生成。

### 2.5 流程层：issue 即工单、PR 即证据包

- **Issue 模板 = AI 可执行工单**：目标、约束（涉及的 KB 编号/层）、DoD、验证命令。工单质量决定 AI 产出质量——人写好工单比人写代码杠杆高一个量级；
- **PR 模板 = 证据包**：门禁结果、基准 delta、矩阵/边界影响声明、AI 生成声明；
- Conventional commits；小 PR（软上限 400 行 diff，核心算法 200 行）；
- **决策记录（ADR-lite）**：架构与语义裁决落 `doc/design/decisions/`，一事一文——AI 可检索历史裁决，避免同一问题反复咨询人。

### 2.6 安全与出处层

- 风险分级变更政策（§3），写入 CLAUDE.md 生效；
- PROVENANCE 纪律扩展到 AI：指令层面禁止复现 GPL 实现与旧核 i5 残留文件（rewrite-plan §0 清单）；R4 相似度抽查覆盖 AI 产出；
- 发布 tag、LICENSE/NOTICE、对外承诺：AI 只起草，落地仅人。

## 3. 风险分级变更政策（随 CLAUDE.md 生效）

| 级别 | 范围 | AI 权限 | 人的角色 |
|------|------|---------|----------|
| **T0 自由区** | 文档、注释、demo、新增测试、格式化、CI 脚本 | 自主推进，门禁绿即合 | 事后抽查 |
| **T1 常规区** | 非 RT 路径实现、工具链、pyplcopen、构建配置 | 实现 + 自检 + 证据包 | 轻评审（过目证据） |
| **T2 核心区** | RT 周期路径、OTG/规划器算法、状态机语义、公开 API | 实现 + 全门禁 + 24h 冷却 | **逐行评审** |
| **T3 禁区** | LICENSE/NOTICE/PROVENANCE、发布 tag、安全边界对外声明 | 只起草，不落地 | 人执行 |

## 5. 有效性度量（季度复盘时看）

| 指标 | 健康信号 |
|------|----------|
| 人评审时间占比 | **< 30% 且下降**——不降说明改造失败，这是首要指标 |
| T0/T1 自主合并占比 | 上升 |
| 门禁拦截数 vs 逃逸缺陷数 | 拦截 >> 逃逸 |
| 变异分数（抽查模块） | ≥ 70% 且稳定（防假测试） |
| 回放 diff 意外率 | 趋零（语义控制力的直接度量） |
| 反模式警报 | AI 代码产量暴涨而合并率下降 = 工单质量问题，先修工单再怪模型 |

## 6. 不变的人类职责

架构与语义裁决、规格审批、T2 逐行评审、硬件在环与实测签字、发布与法务、灯塔用户与社区。以及一条元职责：**维护这套体系本身**——门禁松了、文档漂了、工单懒了，AI 的产出质量会先于任何指标告诉你。
