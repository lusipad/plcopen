# Governance

plcopen is currently a single-maintainer open-source project in a personal
GitHub namespace. It is not governed by a foundation, company committee, or
certification body.

## Roles

| Role | Authority |
|---|---|
| Maintainer | Roadmap and semantic decisions, merges, repository access, release authorization, and external commitments |
| Contributors | Proposals, implementation, tests, documentation, and verifiable evidence |
| AI tools | Work within an approved scope; they are not maintainers, voters, signers, or successors |

The current bus factor is 1. There is no second maintainer or named successor.

## Decision precedence

1. Repository operating rules and skills.
2. Normative compliance documents and known boundaries.
3. Accepted architecture decisions.
4. Current project facts.
5. Current roadmap commitments.
6. Long-term vision.

## Releases and external commitments

Tags, GitHub Releases, package publication, licensing changes, security
disclosure decisions, and public commitments require the authority described
in the
[canonical governance document](https://github.com/lusipad/plcopen/blob/main/GOVERNANCE.md).
CI success alone does not grant that authority.
