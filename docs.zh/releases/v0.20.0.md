# plcopen v0.20.0

`v0.20.0` 是围绕重写后的 `core/` 运行时构建的首个正式 pre-1.0 检查点。
它将 C++17 header-only 运动内核、面向运动控制的 IEC 61131-3 ST 运行时，
以及 Python 仿真 facade 打包为一个版本化发布，用于评估、集成与仿真。

这仍然是一个 pre-1.0 发布。它不声称稳定 ABI、PLCopen 或安全认证，也不声称
已在真实机械上完成生产验证。

## 安装

### 使用 FetchContent 集成 C++

```cmake
include(FetchContent)
FetchContent_Declare(
  plcopen
  GIT_REPOSITORY https://github.com/lusipad/plcopen.git
  GIT_TAG v0.20.0)
FetchContent_MakeAvailable(plcopen)

target_link_libraries(my_controller PRIVATE plcopen::plcopen)
```

导出的 target 为 header-only，要求 C++17 以及 CMake 3.21 或更高版本。
也支持通过 `find_package(plcopen CONFIG REQUIRED)` 消费已安装包。

### Python

```bash
pip install pyplcopen==0.20.0
```

已发布的 wheel 覆盖 Windows、manylinux x86_64 与 macOS x86_64/arm64 上的
CPython 3.10-3.13。对于其他受支持的源码构建环境，提供 sdist。

## 用户将获得什么

- 一个 C++17 header-only 运动控制内核，提供确定性周期执行、jerk-limited
  在线轨迹生成、固定时间求解、blending/look-ahead、gear/cam、笛卡尔运动、
  坐标系、运动学以及 trajectory streaming。
- 重写后的 `core/` 树作为默认 `plcopen::plcopen` consumer target。此前的
  `src/` 实现仅保留为显式 opt-in 的 P0-only 迁移与回放基线。
- PLCopen 风格软件表面，覆盖 Part 1 单轴运动、68/68 个 Part 4 同名 facade，
  以及 11/11 个 Part 5 回零与在线参考功能块。未支持模式和正式声明缺口会被
  明确暴露，而不是静默降级。
- 一个确定性的、面向运动控制的 IEC 61131-3 ST 编译器与 bytecode VM。
  已声明的 L0-L7 与 L-all 特性集包含 134 个标准功能块和 1,476 个 pins，
  没有待补齐的原生适配器条目。
- `pyplcopen` 仿真，覆盖单轴运动、trajectory streams、`PoseArmSim`、
  cam-table 生成和 SI 单位周期配置。
- 一个从规划到 committed trajectory 再到 RT 的参考执行器，以及 replay
  fixtures、周期 trace、RT 安全检查、诊断与生产集成指南。

## 兼容性与迁移

- `v0.20.0` 仍低于 1.0。公开变更遵循 SemVer 并有文档记录，但尚不承诺 ABI
  稳定性。
- `plcopen::plcopen` 现在解析到新的 header-only `core/` target。只有在维护
  迁移或回放基线时，才显式启用冻结实现 `PLCOPEN_BUILD_LEGACY=ON`。
- 新 C++ facade 中的公共字段使用 `snake_case`，功能块输出收拢在 `outputs`
  下，应用通过显式周期调用推进轴/组对象。
- 仓库包含本地 Conan recipe 和一个草案版 vcpkg manifest，但本次发布并不
  声称已发布到 ConanCenter 或 vcpkg registry。

API 与运行时模型的变化见
[migration guide](https://github.com/lusipad/plcopen/blob/v0.20.0/doc/migration-v0-to-v1.md)。

## 已知限制

- 这是一个可嵌入内核，不是完整的 PLC IDE，也不是完整的 IEC 61131-3 平台。
- 不包含 PLCopen 批准、安全认证、SIL/PL 声明或官方 logo 使用权。
- EtherCAT 产品集成、真实设备 72 小时证据以及长期硬件验证仍是未完成工作。
- Feetech 适配器目前是协议层和仿真器，不含生产 IO；动态单位和部分状态位仍
  需要官方来源与真实设备验证。
- vcpkg/ConanCenter registry 发布，以及稳定 ABI/LTS 承诺，仍不在本检查点
  范围内。
