# 已知边界

已知边界（`KB-NNN`）是相对 PLCopen 规格或冻结 v0.x 实现的已声明行为限制。
它们属于合同的一部分，不是非正式 bug 清单。

## 如何使用注册表

1. 按功能块、子系统或代码、测试、issue、发布说明引用的 `KB-NNN` 检索。
2. 阅读 `doc/compliance/` 中对应的语义矩阵。
3. 修改行为前，确认矩阵点名的测试。
4. 若有意改变周期输出，在同一变更中更新 KB 条目和回放基线。

完整的只追加注册表位于
[权威已知边界文档](https://github.com/lusipad/plcopen/blob/main/doc/compliance/known-boundaries.md)。

## 注册表覆盖什么

- 功能块输入组合与不支持的 mode。
- 命令所有权、buffering、blending 与接管行为。
- 不能证明硬件真实性的软件级声明。
- 实时与内存分配边界。
- 新内核与冻结旧线之间的兼容差异。

## 边界意味着什么

边界可能是有意的产品限制、标准缺口，或需要外部硬件证据的行为；它不一定
表示实现有缺陷。反过来，没有 KB 条目也不会自动产生超出公开 API 与语义
矩阵的新保证。
